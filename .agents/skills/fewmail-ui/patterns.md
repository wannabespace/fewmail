# Fewmail patterns

## Controls

- **Control family** (kit): level-3 fill + `shadow-xs` + hairline `border-foreground/4` with `bg-clip-padding` (hover `border-foreground/12`). The hairline is the border, never an outer `ring`: a ring draws outside the box, so a ring-drawn field sat 2px taller than the button beside it (SKILL.md rule 15). Cards and panels keep their outer ring; they never share a row with a control. Hover is `bg-accent`, the one hover surface ([colors.md](colors.md)), never a per-control mix. Focus is `focus-visible:focus-ring`, invalid is `aria-invalid:invalid-ring` — the kit `@utility` pair in globals.css. The focus ring snaps on and only fades out: `focus-ring` drops the control's transition while focused, since a 200ms fade-in reads as lag behind the caret. Focus is always accent and never tinted by state; a control dialing its own `ring-*` pair is the utility going stale, and a `border-destructive` under the invalid ring gives an invalid field more weight than a focused one. Floating panels take the same hairline and `shadow-xl`.
- **Disabled is `opacity-50` + no pointer events on the whole control**, carried by the surface the user sees — a composite control reads the state off its own input (`has-[input:disabled]:`) where the primitive exposes no disabled attribute, or a locked picker looks live.
- **A trigger that opens a menu takes no tooltip** — the menu names its items. Either a button acts or it opens a menu, never `+` plus caret.
- **No bare interactive icons**: ghost hover surface + muted→foreground glyph + tooltip — `Button variant="ghost-muted"` (`outline-muted` for that surface; `ghost-destructive` rests at the same muted glyph and turns red only on hover, so a row's icons read as one set). Upgrade bare ones whenever touching a file.
- An icon-only copy button is kit `CopyIconButton` (`custom/copy-button.tsx`): its `label` is both the tooltip and the `aria-label`. Bare `CopyButton` is for one that carries its own text.
- Any other icon-only button is kit `IconButton` (`custom/icon-button.tsx`): `icon` plus `label`, which is both the tooltip and the `aria-label`, with the tooltip's `shortcut` and `side` passed through. A menu or popover opened by an icon is the same `IconButton`, passed as the trigger's `render` — a bare `Button` with `aria-label` there leaves the icon without a tooltip. A hand-built `Tooltip` around a `Button` with one glyph is upgraded to it whenever its file is touched.
- Icons are Hugeicons only (`HugeiconsIcon` + `@hugeicons/core-free-icons`, `strokeWidth={2}`). Fixed glyphs per concept: Home `Home01Icon`, Mail `Mail01Icon`, Rules and teaching a rule `ZapIcon`, Settings `Settings01Icon`, search `Search01Icon`, board `DashboardSquare01Icon`, anything new `Add01Icon`, compose `PencilEdit02Icon`, check mail `RefreshIcon`, ask AI `AiChat02Icon`, upgrade `CrownIcon`, themes `Sun03Icon`/`Moon02Icon`/`ComputerIcon`. Sidebar row icons sit at `size-4`, 70% opacity, `gap-2` before the label. A glyph that flips with state is one icon with a ternary on `icon`, never two branches.
- Shortcuts render through `ShortcutKbd` (`core/keyboard/`, over the kit's `KbdHotkey`) by id, never a hand-built `Kbd`; a key is a Hugeicons glyph, never the unicode character — ⇧ is `ArrowUpBigIcon`, never an arrow that reads as ↑; ⌫ has no Hugeicon, so the kit draws its own in the same stroke, never the trash can. Modifiers follow macOS order ⌃⌥⇧⌘ (⇧⌘E, never ⌘⇧E). A `Kbd` sizes itself to its host: full size inline, compact (`h-4`, `text-2xs`, 10px glyphs) inside a tooltip or a menu row's shortcut slot, so call sites pass no size. A `Kbd` has no background anywhere — a tinted chip vanishes on coloured buttons and dark surfaces, so shortcuts read by muted text alone. **A button never draws its shortcut in its label** — not a `Kbd`, not a hand-rolled `Esc` span: the hint lives in its tooltip (next bullet). Search fields keep their always-visible ⌘F hint in the field's end slot.
- A key drawn as a physical key is `Kbd variant="keycap" size="lg"`, animated through `KbdMotion`, never a hand-built raised span.
- **Holding ⌘ shows each control's shortcut glyph, nothing else.** A control with a shortcut passes its `Kbd` as the kit `Tooltip`'s `shortcut` prop, never inside `TooltipContent` (the kit appends it); pass nothing while the control is disabled or the key does not fire here (`window.electron && <Kbd…/>` for Electron-only keys). Hover shows the label plus the glyph; once `useShortcutReveal` reports ⌘ held for a beat (never, while the user has turned it off in Settings → Keyboard), the tooltip opens with the glyph alone, so neighbouring controls' hints stay small and apart, and nothing reflows. A control something else covers (under an open menu or dialog) shows no hint — the kit hit-tests the trigger as the reveal starts, so a menu shows only its own rows' shortcuts. Pressing a shortcut mid-hold ends the reveal until ⌘ is held again, since the dialog or menu it opens would otherwise sit under hints already shown. Two hints that still meet take different `side`s. A control that only appears on hover (a tab's close button) also takes `data-popup-open:opacity-100`, or the hint points at nothing. A hover-only per-row control whose key acts on the cursor row (a mail row's Archive `E`, Trash `⌫`; in Archive, Spam and Trash `E` brings the thread back instead — Move to inbox, or Not spam — and the row's button, the thread's button and the hint follow, via `sweepOf`) passes no shortcut — the hovered row is rarely the cursor row, so the hint would show on one row and lie on the rest; the key lives in the page's `KeyHints`. A text button with a shortcut gets a tooltip for it too — the tooltip exists to carry the hint.
- **Nav fires on mousedown** (`~/components/link.tsx`, never router `Link`); menu items activate on click (macOS semantics). Imperative press-nav uses `pressNavProps`.
- Tooltips never nest triggers, and multi-node prose goes in **one** block child — `TooltipContent` is `inline-flex`, so sibling nodes lay out as columns. Rich content (a card with icon, heading and paragraphs) is never a tooltip: it is a `Popover` with `openOnHover`, so it gets the popup surface instead of the inverted tooltip ink.
- **Column facts read as SQL clauses**, one per line (`PRIMARY KEY`, `REFERENCES users(id)`, `NOT NULL`, `DEFAULT now()`), never paraphrased labels or constraint names: the audience reads DDL, and invented wording is what they cannot parse. The one exception is `NULLABLE`: a bare `NULL` reads as a value. Set as code with keywords dimmed and identifiers and values at full ink, so the eye lands on what differs per column.
- A `link` button owns its horizontal padding; `px-0!` at a call site is fighting the kit. A lone text action under prose (not in a row of buttons) is `link-muted`, so its glyph starts on the text's edge, and its hover only underlines, keeping the muted colour; a ghost button's padding insets it, and an outline adds a box the prose doesn't have.
- **A command, file or name inside a sentence is kit `InlineCode`** (`components/custom/inline-code.tsx`, also Markdown's inline code and every backticked part of a `FetchingReason`): a `bg-current/10` pill in the colour of the text around it, sized `0.9em` of it, so it reads on the canvas, a card, a muted line and an inverted tooltip in both themes. Inside a flex container (a tooltip, an item title) the sentence goes in one span, or each piece becomes a column. A bare `font-mono` span reads as a typo, not a command. A value the user copies stays muted mono text before its copy button (Settings).
- **A secret is masked unless revealed or being edited.** A one-line secret is kit `PasswordInput`. A multi-line one (an SSH private key) is a textarea while empty, focused or revealed, and otherwise a read-only one-line password input showing its first line, where a paste replaces the whole key: a password input drops line breaks, and a masked textarea scrolls to its caret and shows partial lines. An eye `IconButton` flips it, the same glyph pair as `PasswordInput`.
- **Leaving Edit with unsaved changes asks first**: a router blocker opens an `AlertDialog` (Keep editing, destructive Discard). It ignores the save's own navigation and never vetoes `beforeunload`, which in Electron cancels closing the window with no prompt. Create and the unlock form don't ask: nothing there is a saved record to lose.
- Rows that repeat a label inside another card (the SSH tunnel's Host, User, Password) keep the short visible label and take an `aria-label` naming their group (`SSH host`), so a screen reader tells them from the server's rows.
- **Segmented `Tabs` sit on a `foreground/6` track** so they read on every surface, including the canvas (`muted` matches `body` in dark). A filter strip with more than three options in a resizable pane (mail filters) is the `pill` variant — trackless chips, the active one an ink pill (`bg-foreground text-background`), counts at 60% opacity so they read on both — scrolling sideways (`max-w-full overflow-x-auto scroll-fade-x scrollbar-none`); a segmented track overflows its pane and gets clipped mid-pill, and `line` tabs read as page navigation rather than a quick switch.
- **An off `Switch` sits on a `foreground/15` track**, never `muted`: in dark `muted` matches the canvas and the off track vanishes, leaving a bare thumb.
- **The Mail header is one row: the view picker, the mailbox `Select` (only with several mailboxes), and a Search icon button at the end.** The picker is one outline `sm` `Button` (the view's glyph, its name, the unread count as muted `tabular-nums`, a chevron) opening a `w-120` popover of **inbox views**, the way Spark does it: three cards in a row, each a miniature of the list on top (`ViewSketch`: a level-3 sheet on a canvas well, its rows marked the way the view sorts them), then the name and up to three lines of what it holds (`mail.filterAbout`), no counts (every view counts the same unread inbox); the folders live only in the sidebar, never in this popover, which then shows the folder's name on its trigger. The views are layouts of the same inbox, not slices of it: **Focused** (`FlashIcon`, the default) groups it by what the user does with it, the way Superhuman, HEY and Apple Mail split an inbox (`GROUP_OF` in `mail.tsx`): Important (importance ≥ 2, whatever its kind, so time-sensitive mail never hides in a folded group), People (`person` / `work`, and recent mail not analysed yet, never from an automated address: `isAutomatedSender`), Calendar and travel, Money (bills and receipts), Notifications (services, security, other), Newsletters, Promotions, then Earlier (old mail never analysed); **Unread** (`InboxUnreadIcon`) groups only unread mail that way and puts the rest under Read; **Inbox** is one list, newest first. Money, Notifications, Newsletters and Promotions are **folded**: their newest three, with Show all N / Show fewer at the end of the group header, so noise never pushes people's mail away. People is decided by the sender's address as well as the classifier, since a classifier reads a Google Cloud billing notice as work. There is no separate Group by control, since fourteen buttons in one popover read as settings nobody opened. The picked view is remembered per browser (`fewmail.inbox-view`) and `?filter=` overrides it. Picking a view closes the popover; the active card takes the onboarding preset ring (`ring-2 ring-primary`). `[` / `]` step through the views and folders. In Unread, a thread opened from an unread group stays there until the list changes (`keptUnread`), so reading never moves the rows under the cursor. **Search is its own page** in the list pane (`?q=`, empty while nothing is asked), opened by the Search button or `/`: a back button, one `sm` search field (a muted `Spinner` at its end while a query waits) and the mailbox select; with nothing typed it shows Recent (per browser, six, with a `link-muted` Clear in its header) and Tips (Gmail operators that work on received mail, plus one plain-language example only with the agent) as one-line rows in the list's own grammar (sticky section headers, `border-b` rows, glyph, operator, muted hint at the end), never chips or a card grid, so typing swaps rows for rows; picking an operator adds it to the field, and one ending in `:` is not searched until something follows it. It searches all received mail ungrouped, whatever view was picked. The reader pane never folds for search: a pane springing shut on `/` and open on every result read as the page breaking. Typing must stay instant: the field is uncontrolled and the list follows it in a `startTransition`; local matches show at once, the server's answer (debounced 400ms, `⏎` at once) is merged into them by thread, newest first, and the last answer stays while the query is refined, so results grow and shrink instead of blinking empty, and the list is never dimmed while searching (the field's spinner says it). `↓` in the field moves the cursor into the results. Escape steps back one level: close the thread, clear the query, leave search. Unread rows sit on `bg-background`, read ones on the canvas, so read mail shows at a glance. **Pinned threads open every inbox view** under a sticky Pinned header (count, then a `link-muted` `xs` Show all N / Show fewer at its end): one line each (dot, sender at most 2/5, subject, time), the first three only, so pins never push the inbox down; the list below leaves them out, and the cursor walks the shown pins first. Their hover icons sit at `top-1` to centre on the shorter row; every row's hover set starts with Pin / Unpin (`PinIcon` / `PinOffIcon`), `S` on the cursor row or open thread. Group headers are sticky `bg-body` rows (label + count at 60%) aligned with the row text; the cursor walks rows only, in group order.
- **A Mail list never ends where the database does.** Its first page is held mail; scrolling within 600px of the end (an `IntersectionObserver` on a last `li` inside the list's own scroller) reads the next page of the view's own list, past `heldSince` straight from Gmail, with a muted `Spinner` holding the place, until a page comes back empty. A list with nothing held shows that loader, not its Empty state. In Focused and Unread, mail that was never analysed (older than the analysis window) groups under **Earlier**, after Newsletters and unfolded, never under People: People's unanalysed mail is only mail on its way to analysis. **A pointer on a mail row warms it** (`warmThread`): the thread loads and the newest email's images go into the browser cache, so the reader's frame paints at once; images sized 2px or less (tracking pixels) wait for the open, so a hover never tells a sender the mail was read. Rows warmed ahead by the keyboard cursor load only the thread.
- **A one-of-few choice inside a form is a flat `Select`** (below). `Tabs` only switch panels; a row of outline buttons with one filled reads as several actions.
- **A control that submits itself shows its own pending state.** With no button to carry `LoadingContent` (a code input that verifies on the last digit), a muted `Spinner` sits beside the control, positioned out of flow so nothing shifts, and stays through the navigation that follows the request — a dimmed input alone reads as frozen.
- **A server-rendered data page awaits only what its header needs.** The loader awaits the cheap metadata (name, description, filters, so the page head and title are real) and starts the slow read without awaiting it; the table is its own Suspense boundary whose fallback is the kit `TableSkeleton` (`@fewmail/table`) inside the same box, and a header line fed by the read (an updated time) gets a skeleton bar of its exact line height. So the server streams the real header with the skeleton at once and nothing above the table moves when rows arrive. A page-level skeleton cannot know whether the optional header lines exist, so it always shifts something. A re-sort keeps the page: the read uses a `useDeferredValue` of the search, the old rows stay, and the table skeleton covers only the grid on a 150ms CSS delay so a cached sort never flashes.
- **A nav link answers the click before the page does.** Its active state follows the pending location the moment it is pressed. The page area hands over to the route spinner only after a beat: while a different path loads (`status === 'pending'` with a changed pathname, so an invalidate or a search-param change never counts), the page fades out and the spinner fades in, both on a 150ms CSS delay, so a cached page swaps with no flash and only a slow one shows the loader. The router's own pending component never appears here — navigation renders in a transition, which keeps the old page up instead of showing a Suspense fallback.

## Popups and menus

- Context menus are always `AppContextMenu` (data-driven node tree; base-ui on web, native menu over IPC on desktop), never raw kit menu primitives. Destructive item last, after a separator. Every action item and submenu carries an `icon` (hugeicons data, not a node); native menus show its SF Symbol twin from the `sfSymbols` map in `AppContextMenu` (macOS `nativeImage.createMenuSymbol`) — a new icon needs a map entry or it renders web-only. Names are typed (`SFSymbol` from `sf-symbols-typescript`), but the type covers the newest SF Symbols release: a symbol newer than the running macOS still renders empty, silently. Leaf lists that read as options (filter operators, radio choices) stay icon-less.
- A function `items` resolves when the menu opens, on web and native alike, so one menu per card can pick its items from a ref the right-click just set (the diagram's table/column menu).
- **Open in New Window** is the first item of any row menu standing for a route, above a separator. The target must exist before the window opens (a table registers its tab first); `openNewWindow` takes the route href. Secondary desktop windows open offset and never restore maximized — landing on top of the window you came from reads as nothing happened.
- Popups keep the kit's density and radius — don't re-inflate or shrink. `DialogContent` is `p-5` with a `gap-4` grid; the registry's `p-6 gap-6` read as empty against the app's row heights (`AlertDialogContent` still has it). `PopoverContent` owns padding through its `padding` prop (`none` also flattens the base-ui viewport slot); a call site writing `p-0` plus a slot override is the prop going unused.
- **A preset menu ends with a custom pick.** Time presets (Send later) list as an icon-less menu, then a separator and `Pick date & time` (`Calendar03Icon`), which closes the menu and opens a popover anchored to the same trigger: the kit `Calendar` (past days disabled, the user's locale and week start) over a time `Input` and a submit `Button` in one form, so ⏎ in the time field schedules. A time already past marks the field `aria-invalid` instead of scheduling.
- Popovers keep 8px off the window edge and never outgrow the window; a wide fixed-width popover shrinks instead of hugging the edge. The kit caps the height at `--available-height` too, so a tall popover's scrolling body must be a `min-h-0` flex child, or it overflows the cap instead of shrinking.
- Popovers size to content (`w-auto min-w-40`), menus cap at `max-w-80`; only `Select` and `Combobox` match `--anchor-width`, since a menu row is usually longer than its trigger. `CommandInput` only at ~8+ items; hide a sole group heading.
- **Command popups**: state lives as rows in the one `CommandList` — a pinned block outside it is invisible to filter and arrows. The row is the button (state = glyph on the row), a two-state control is one flipping icon, and a picker belongs in the same popover's body, never a child popover. A hover-only ✕ is never the only way out; a nested trailing control `stopPropagation`s on `onPointerDown` *and* `onClick` (cmdk selects on click) and sits absolutely inside the row.
- A hidden control still holds its space, and a control that only appears on hover never moves out from under the pointer.
- **Dashboard rows are one ↑/↓ list** — Last Opened, the connection rows and New connection — entered with ↓ from an unfocused page; a focused connection row takes the hover fill plus an inset focus ring, since the card clips an outer one.
- **A dashboard row with no link yet shows its loading state**, never a normal look that ignores clicks: while its database's resource row is being fetched, it pulses with the spinner beside the name.
- The `AppMenuButton` ⋯ is always visible in dashboard rows, definitions tables and column headers. Only the navigator's sidebar rows reveal it on hover, because the row's pin can take its place there. A row or header carrying a ⋯ also opens the same items on right-click (`AppContextMenu` on the row or header, one shared `items` function).

## Lists and tables

- **A row's one-time code is a split button** at the row's bottom right, always shown: outline `xs` code (copies) + separator + outline chevron in a kit `ButtonGroup`, whose menu holds Copy and archive / Copy and delete. Loose hover icons beside a chip read as stray clutter.
- **Mail rows are two lines, Spark's density with Gmail's full subject.** Line one: unread dot (`bg-primary`, an empty slot when read), sender, then the row's facts in muted `text-xs` pushed to the right beside the time (extracted chips first as `sm` badges, the same height as the thread count, then category, expects a reply, attachment, bulk; what does not fit drops out whole, the sender keeps its width first), importance dot, time; line two: the subject, one line. No summary or snippet line: the subject says what the email is, and a third line made the list half as long; the summary lives in the open thread. Never a line of facts under the subject either. Unread rows carry a semibold sender, a `font-medium` `foreground/90` subject and an ink time; read rows drop to `foreground/70` sender, `foreground/60` subject and a muted time. A row is a thread: a thread of several emails shows its size after the sender as an outline `sm` `Badge`. A bare number and the category beside the sender read as one phrase ("GitHub 2 Notification"), so the count gets an edge and the facts sit apart at the right: who on the left, what on the right. Separate threads one sender sends within 10 minutes of each other (a retried payment, a split notice) fold into one row with `N emails` after the sender (`collapseBursts`), until it is opened or → expands it. In place of the subject line it lists its emails newest first, one line each (subject, muted time, aligned with the subject), in a kit `ScrollArea` capped at about four lines (`max-h-28`, `scroll-fade`), each line a `hover:bg-secondary` pill that opens that very email, so a burst never makes you read the wrong one first; its hover icons and E / H / # / ! act on every email in it, and their toasts share an id so one answer shows. The open thread's row is `bg-secondary` with no hover, a step past the cursor's `bg-accent`; the cursor stays hidden until the first J / K / arrow (and after the view, mailbox or search changes), so a fresh list never shows a filled row that reads as flagged, and E / H / # act on nothing until then; the cursor follows the open thread wherever it lands (opened from a link, or moved when new mail reshuffles the list), so a second filled row only appears when J / K walk away from it.
- **A row unfolds its sender's other threads.** Opening a row (or → on the cursor row, with `→ more from sender` in the key hints while it would show anything) lists under it, one line each (`pl-9` subject, muted date), up to five other threads from the same address found in any of the mailbox's lists but Pinned, Spam and Trash, newest first, never one the list already shows (`useRelatedRows`). They are real list rows: J / K walk into them, ⏎ opens one without moving the anchor, E / H / ⌫ act on it; ← folds them and puts the cursor back on the row. Group headers are keyed by their first row's id, so rows inserted mid-list never shift them.
- **Unread counts mirror Gmail.** The view picker (on an inbox view — not Snoozed, Drafts, Archive, Spam or Trash) and the sidebar Mail row show the unread count of inbox mail as plain muted `tabular-nums` text (`mail.unread`); the filled `bg-primary` pill stays reserved for Home, where the count is work waiting.
- Grouped lists: one `rounded-xl border bg-card` container, `border-b last:border-b-0` rows, `hover:bg-accent`.
- **A `SettingsGroup` list walked with J / K** marks the cursor row with `SettingsRow active` (`bg-accent`, the mail list's cursor surface) and shows the row action's key only on that row's button (Subscriptions: `U`).
- **A page list's search gets its own full-width row** under the count and controls row, at default size, bleeding with the card under it (`smallItemBleedClassName`) so both share one width. Squeezed among the controls it truncates its placeholder; stripped of its surface it stops reading as a field. Matches are highlighted in the rows.
- **A settings row's description fits on one line beside its control.** When the explanation runs longer (a row that shows a value to copy, like the forward address), it goes behind an info glyph after the title (`SettingsRow hint`, a `ghost-muted` `icon-2xs` `IconButton` whose tooltip is the text), never as a description truncated to two lines.
- **A settings row that opens a page is the whole row as a link** (`SettingsRow render={<Link … />}`, Legal), never a link inside the title: the row takes the hover fill and the text stays foreground.
- **Text aligns, cards bleed.** A `SettingsGroup` card hangs outside the page column by its rows' inset (`smallItemBleedClassName`), so the page title, the group label ("Teach a new rule", "4 rules") and the row text all start on one line; the label takes no inset of its own. Rows and content inside a card (header row, inset `CodeBlock`) take the kit's `smallItemInsetClassName`, never a copied `px-3.5`, and the bleed moves with it. Home's queue cards (`Accordion variant="cards"`) and their empty state bleed the same way by the trigger's inset (`cardsBleedClassName`), so the card numbers line up under "Worth your attention".
- Data table: ghost cell controls only (outline buttons down a column fight the values); **a hairline grid, no zebra**: every row takes a bottom rule and every column, header included, a right rule (the gutter and the trailing column take none), since cells edit in place like a spreadsheet. Hover stays `bg-accent`; the skeleton draws the same rules. Skeleton bars are deterministic (`pseudoRandom` seeded by index), never `Math.random`.
- **Data table cells read as sans** (values are data, not code); only the editor's JSON/XML view is Monaco. The cell cursor ([colors.md](colors.md)) is the grid's keyboard home. One context menu serves every cell, resolved from the cursor the right-click just placed — never a menu per cell.
- **Header = property row**: one line, the column's kind as a muted glyph before the name, like a Notion property — the DDL clauses live in a tooltip, never as a second line. The resize grip ends on the column rule at full header height, never past it (see [gotchas.md](gotchas.md)). **Clicking a header cycles its sort** ascending → descending → off: an unsorted column replaces the sort (⇧-click adds it as the next level), a column already in the sort cycles in its place and keeps the rest, so a stray click never wipes a multi-level sort. The press is the drag's too: past a few pixels it reorders instead (cancelled or not), and the header's own controls (⋯, grip), its portalled menus and a press that closes an open cell edit never sort. The keyboard route is the column menu.
- **Values render by type**: booleans are a kit `Checkbox` flipped in place — never a text editor; enum values a secondary `Badge` led by a coloured dot (Finder tags; the hue lives on the dot only, so the chip text reads in both themes; colour = the value's position among the column's values, else a hash); a multi-value row of tags that overflows the grid cell fades out at its right edge (a mask, not a measured `+N`), so a clipped chip reads as "more", not a rendering bug; numbers, dates and times left-aligned `tabular-nums` (a column of values reads from the left); a time whose stored offset differs from the viewer's keeps the stored text first at full ink (what the engine holds is what people read the grid for) and follows it with the viewer's wall-clock time, muted, its tooltip naming the zone (no glyph: the muted second time already reads as a conversion), dated only when the day differs; NULL a muted `null`.
- **Editing is a level-3 card over the cell**: a `Popover` anchored on the cell with `sideOffset` of minus the cell's height, so it covers the cell from its top-left and base-ui's collision handling flips it up (bottom on the cell's bottom) or shifts it; at least the cell's width; the cursor ring hides while it is open. Text is a flat growing `Textarea`, dates and times included (no calendar: timestamps are typed or set with `Now`); enum values open a tag `Command` list as wide as its longest value (window-capped), since enum values often share a long prefix and a truncated tag cannot be told apart; JSON and XML open Monaco. A foreign key opens a server-side search over the referenced table matching the key and every text-like column, so a person's name finds their id; each option is the key over a muted preview of the row, and Enter on no match still saves what was typed. An untouched edit lists the current value first, so Enter keeps it. A nullable, editable column always ends the card with **Set null**, the one way to NULL in every editor. The edit's text lives in the cursor store, so it survives its row scrolling out and back.
- **An edit commits like a Finder rename**: clicking anywhere else applies, leaving the window does not. A rejected value keeps the card open with an inline destructive message, never a toast — except a foreign key's search card, whose text is a search, not a value: no row matching is said by its list's empty state, and a type error under "No matching rows" would only repeat it in the wrong terms. Enter with no match still applies a well-formed key (the engine judges the constraint, which may be deferred or unenforced); malformed text just stays in the search. A column whose DEFAULT the engine can write back in an UPDATE offers **Default**, shown in the cell as italic `default`. The keys are the spreadsheet's (`docs/features/table-browser.mdx`).
- **Cell blocks are spreadsheet selections**: copy and paste move TSV, one value fills a block, and rejected pasted values are counted in one toast. A right-click inside the block keeps it. Two or more selected cells add a summary (count of filled cells; sum, average, min and max for numeric columns) to the grid's bottom dock.
- **The grid's bottom dock holds pending and selection actions, never the toolbar.** One glass bar centred over the grid's bottom edge (`GridBar`), its items in a fixed order: the cell-block summary, checked-row Export, checked-row Delete, then unsaved changes (Review, Save), so the primary action ends the bar on the right. Export sits only here, never in ⋯ too, and takes the checked rows already loaded, since a selection never holds a row the grid has not loaded. Every export menu asks in the same order, row count (when there is one to pick), format, then **Download** or **Copy**, so each choice is listed once and no level repeats another. Conditional actions in the toolbar would push the filter field sideways; the dock keeps the toolbar still and sits by what was selected. Callers pass items through `DataGrid`'s `bar`; the summary is the grid's own. Review and Export are `ghost-muted`; Delete (`destructive`) and Save are filled — a ghost button's invisible padding makes the dividers look unevenly spaced. Export is an icon with a tooltip, since the bar can already run wide and Delete beside it shows the count. Counts on its buttons are a `NumberFlow`; the selection summary's stats are plain `tabular-nums` text, since they change on every arrow press and rolling digits there read as noise. A stat past a million shortens (compact, then scientific from 10¹⁵, where compact would grow digits again) and keeps the exact value on hover, so the bar never outgrows the grid; integer columns are summed as `BigInt`, since drivers hand `bigint` over as text and `Number` rounds past 2⁵³.
- **JSON quick look** is a cell-owned popover, so virtualization unmounting the cell takes it away; moving the cursor or editing clears it.
- **Pinned columns** lead the grid in pin order, sticky, opaque and hovering with their row, and a drag never moves them. **Distinct Values** hangs from the header in a table-level popover, never inside the header, whose drag and menu handlers would take its events. **Show Labels** on a foreign key keeps the key first at full ink (it is the stored value, like a time before its conversion) and follows it with the referenced text column's value in muted text, like a time's local conversion, never a chip: the key truncates first, since a long id would otherwise push the label out. The label is capped at two thirds of the cell so the key always shows; the default comes only from a short list of conventional label names, never a guess beyond it. A column showing labels or a time zone conversion defaults wider to make room for that text.
- **The grid's leading column is pinned to the left edge**: it holds only the row checkbox, one row-height square, and exists only on tables whose rows can be found (`rowIdentity`: a primary key where keys are unique, a unique key with no nullable column, or the comparable columns). Identical rows share one key, so ticking one ticks all of them and the Delete count and select-all count ticked rows, not keys. A new row shows a discard button in that square instead, since the row is not saved and cannot be selected. Scroll padding spans the gutter and every pinned column, so a revealed cell never lands under them.
- **References peek, never navigate**: one peek per grid, anchored to the cell and closed when the grid scrolls ([gotchas.md](gotchas.md)). The ↗ (foreign key) / ↙ (referenced by) buttons are glyph-only ghosts, always visible — a reference is a fact about the value, so it never hides until hover. The popover hangs from the cell itself, not the button. One matching row is a record (fields, then a *Referenced by* list); several are a table whose rows open a record, the matched column dropped since every row repeats it. The header is the trail: earlier hops are crumbs that jump back, no separate Back button, and Escape pops a hop before it closes. Hops swap with an instant exit — a cross-fade layers two tables of different heights. No scroll fades in the peek. The peek is read-only; ↗ inside it always means *show it here*, and leaving for a tab is only the labelled **Open in Table** button.
- A connection this device cannot query opens to the pane empty state carrying the blocking reason and one outline Back, never to the error page. What the user can supply here is not a dead end: missing secrets, or the server details a metadata-only sync never brings, open the connection's own form in place, identity card hidden and every field the device already holds disabled for context, so there is one form for a connection's details, never a separate credentials screen. Name, label and color change only from Edit. Empty states use kit `Empty`; a pane-level one is the kit's icon empty state (icon + title + one line, the app and the share site's one component) on the pane density `Empty size="sm"` (full-page states take the default size) with a `muted` or `destructive` `EmptyMedia` tile — anything added competes with the emptiness, and the emptiness is the message. The one exception is a way straight back to work: a failed runner statement offers "Fix with AI" under the error, and the connection's empty pane lists recent tables under the text as ghost `sm` `Button` links, headed by a muted `text-xs` "Recent" label aligned to the rows' inset. A popover list's empty state is its `CommandEmpty`: a muted icon over one `text-xs` line, no tile, no title.
- A pane-level **error** reuses that scale with a destructive-tinted tile: the title names what failed, the database's own message is the description (mono, masked, selectable), never a generic hint above it, which guesses a cause the message already states. Full text sits behind a ghost `Show details`. An error the user can fix from where they are opens in place with its remedies as buttons (outline for leaving and retrying, filled for the fix), rather than sending them to the error page, so the fix is one click from the cause. A value the app could only guess is left blank until the real one arrives, never shown as fact.
- **Editable value lists** are the kit `EditableList`, never a hand-rolled row stack. It owns the whole keyboard and pointer contract so every list in the app answers the same keys (Enter inserts below the caret, Backspace removes an empty row, ↑/↓ walk, ⌥↑/⌥↓ move the row, Escape blurs, multi-line paste spills, grip drags to reorder), holds itself to one row and marks duplicates itself. A drag reports its order once on release, so a form deriving a plan from the order does not flicker mid-gesture. Ids belong to the call site — a row seeded from existing data carries its own identity while the list mints uuids for rows it adds. The list paints one field surface; the `Add value` button sits **under** the card at the card's size tier, never as a row inside it (a row the user has to read to know it is a button).
- **Documents view is a `DataGrid` layout, never a second table.** Only the body swaps; cells, cursor, editor, cell menu, drafts and references are the grid's own, so a feature added to the grid lands in both. Each document is a run of full-width field rows under a sticky `Row N · <identity>` label (identity is the primary key value, else the first unique constraint's, never a guessed name-like column) — no cards or borders — and the label toggles the row's checkbox. Field labels are the column header in one line and share its menu, minus resize and drag. Arrow axes swap; values wrap and clamp at four lines, and nested JSON opens as collapsibles. The toolbar toggle is one outline icon button whose glyph names the view it switches to, not a latched fill.
- **Filters can go through a foreign key**: typing a referenced table's column offers *Filter by users.email* (`via user_id`), compiled to `user_id IN (SELECT id FROM users WHERE …)`. Its chip reads `users.email`; Copy-as-code hides the ORM formats while one is active, since only SQL can state it.
- **Table toolbar** is a row above the grid like the runner's, on the pane surface (no strip fill), the grid carrying the top hairline; its filter suggestions and menus open downward.
- **Table toolbar counters**: outline buttons sharing one shape, each count on the control that acts on it. **Count always visible, geometry always stable** — `Skeleton` before the count is known (a premature `0` is a wrong answer), `NumberFlow` via the kit wrapper for the changing part, spent state is `disabled` + `disabled:opacity-100`, never a span swap. Invalidate by query-key prefix, never by threading state around to rebuild a key.
- **Review changes is one drawer recipe** for cell drafts and diagram drafts: a pane-density drawer, one card per row or table with a mono identity header at full ink (the column labels below are muted, so the header reads as the row it names), hairline rows, discards as visible ghost `DiscardButton`s (never hover-revealed — keyboard users cannot reach them). A cell-draft card discards on its header, and per change only when the row holds two or more; a diagram card discards per statement. A cell change is a full-width row button — column name and type over `before → after` inline and left-aligned with a long arrow (a centered chevron reads as a breadcrumb), before muted and struck through — and pressing it closes the drawer and reveals that cell in the grid with the cursor on it. No SQL preview for cell drafts: the value diff says it. A failed save's message sits once at the foot of its row's card, never under a change — a row saves as one statement, so the error belongs to the row, and it clears once any change in that row is discarded. Both drawers are `StagedReviewDrawer` with a `ChangeGroup` per card (`~/core/drafts/review-drawer.tsx`); a surface supplies only its groups, description and submit label.
- **A truncated value over a row link gets a tooltip by being a link itself**: the row's overlay link takes every pointer, so the value renders as its own `tabIndex={-1}` link to the same target as the tooltip trigger (muted); a plain `pointer-events-auto` span would leave a dead spot in the row.

## Messages, alerts, and status

- Alerts: `variant` carries the tint, and there is one density (pane scale) because an alert always sits inside a pane, form or dialog. A call site passing its own padding, radius, text size or tint is a missing variant.
- **An `Alert` reports what already happened.** What a pending action will do belongs on the action: the submit button turns `warning` (`destructive` when it destroys data), is relabelled to the real verb, and carries the consequence in its tooltip — no alert above it and no confirmation dialog in front of it. A confirmation dialog is only for an action with no undo and no draft to back out of. "This field is locked because the shape lives elsewhere" stays a `FieldDescription`; a tinted box for it costs the real warning its weight.
- **An action the current context cannot satisfy is disabled with its reason in a tooltip, never opened to a dead form.** The reason names what is missing ("This schema has no tables to index."), and the button keeps `focusableWhenDisabled` so it still takes hover and a tab stop — a native `disabled` button fires no pointer events, so its tooltip never shows.
- **What the agent did with an email sits beside that email, never stacked above the thread.** A thread shows each settled action (`Mark as read · by a rule`, `· done`, `· failed`) as muted `text-xs` next to the date of its own message, in the expanded header and the folded row alike (`ActionNote`); several on one email join with commas. Pending cards stay on Home only — "waiting" in the reader sends the user where they already are.
- **The person panel's count opens the list.** Under a thread, "N conversations" is a `link-muted` `xs` toggle that unfolds the person's latest threads in place (subject linking to the thread, muted date at the end, the open thread unlinked) — no trip to search. The panel exists only for people: a service address (`failed-payments@…`) gets none.
- Global banner: slow and broken connections report there — a page that only spins is the bug. Wording is about the response, never "connecting".
- **Server banners paint from the last list.** The fetch waits a beat after boot, so the previous response (localStorage) is the query's `placeholderData`: a banner that was up last time is there on first paint instead of pushing the chrome down a second later.
- **A tab-wide shortcut binds app-wide, not on one element.** Only the active tab's route is mounted, so ⌘Z over staged table edits uses `useHotkeys` with `ignoreInputs` and no `target`: a `target` binding goes deaf when the focused control unmounts (removing a filter chip drops focus to `body`).
- Toasts use `unstyled: true` + the glass recipe. A title-only toast centers its icon, title and button in the row; one with a description top-aligns, the icon sitting on the title's line. **The `Toaster` portals to `document.body`** — `#root` carries `isolate z-10`, so anything inside it paints under body-portalled overlays whatever its z-index; the list sits at `z-60`, above overlays and below the window-too-small cover.
- **A control a guest cannot use stays enabled and dimmed, never hidden** — `opacity-50`, label and tooltip unchanged, no per-control hint. Its press, shortcut and palette entry run the same path a free user's does: `checkOrUpgrade` (`architecture.md` → Permissions). Never `disabled` — a disabled control swallows the press, and the press is the prompt. A locked `Link` takes `disabled` (TanStack drops the navigation but still runs `onClick`). Native context menus can't dim, so their items just stay enabled.
- **Guest limits live in the global banner, never a toast or dialog.** A guest always sees one info banner ("Many features are disabled until you sign in." + `Sign in`) that stays mounted so the guest sees what signing in unlocks; its main text never changes — `font-medium` in the info tint. Hitting a limit appends one regular-weight line after it in the same tint at full opacity (a dimmed tint reads as muddy) — the feature's hint, or a server refusal's own message — fading in and replaced by the next hit, and shakes the banner gently (±4px, 300ms; reduced motion: flash only) and flashes it. Replacing the main text with the reason reads as noise. A toast reads as a missable notification and a dialog is too heavy for a limit the user will hit again.
- **Plan and usage** (Settings → Plan) is two groups, so where you stand never mixes with what you could buy. **Plan**: the current plan row (its end or renewal day without a year — `formatResetDay` — and Manage billing when paid), then one **This month** row with the reset day as its description and the limits stacked on the right as `w-40` meters (`N of M emails` as muted `text-xs tabular-nums` over a kit `Progress`, `destructive` once spent) — never a row and a hint per limit. **Other plans** (absent on Max): until the user pays, a `Switch` row **Pay yearly** ("Two months free") that flips every price below, then one row per plan the user can move to (`Name · $N / month` or `/ year`, its limits as the description, **Choose**; the cheapest is `default` on Free, the rest `outline`), and on Free a muted line on what Pro adds. A plan limit hit anywhere answers with `t.limits.*` in place (a toast, or inline in the chat instead of Retry), never a dialog. From 90% the account menu's status reads `Agent · N% of this month used` and its avatar carries the dot.
- **A Pro feature on Free is shown, and opening it asks for Pro.** Entry points (nav rows, ⌘K items, menu items, buttons) render as on Pro, never dimmed or badged; their press, key or URL opens the one `UpgradeDialog`: the feature's own label as the title, `t.upgrade.hints` as the description, one autofocused primary `Upgrade to Pro` (`CrownIcon`) to Settings → Plan, no cancel button (Escape and the corner close it). A ⌘K item closes the palette first. Never a second dialog per feature; add a key to `ProFeature` and `t.upgrade.hints`.
- **The sidebar starts with search and compose on one row**: the search trigger fills it (a default-size `outline-muted` `Button`, search glyph and label, ⌘K in its tooltip — a ⌘K in the row truncated the label at the default width), and a size-`icon` `outline-muted` `PencilEdit02Icon` button beside it opens a new email (tooltip "New email" with `C`). Compose was only `C` and ⌘K before, and people could not find how to write an email.
- **The sidebar's lists scroll between the nav and the account menu**: Boards, then Folders (Snoozed `Clock01Icon`, Drafts `FileEditIcon`, Archive `Archive02Icon`, Spam `SpamIcon`, Trash `Delete02Icon`, then each Gmail label with `Tag01Icon`, its name masked) sit in one `overflow-y-auto` region, so many labels never push the account menu off screen. Folder rows are plain links into Mail (`?filter=` or `?q=label:…`), no counts and no keys; ⌘K repeats them under the same heading.
- **The sidebar ends in the account menu**, never loose status text: one nav-height row (initial `Avatar` `sm`, the masked email up to the `@` (the full address fits nowhere in a 200px sidebar; it heads the menu), `UnfoldMoreIcon`) opening upward. Inside: the email over the account's one status line (sync failing, syncing, usage from 90%, trial days, agent watching), Upgrade while free or on trial, Appearance (theme radio submenu: Light, Dark, System — the Appearance heading already says what they are), then Sign out last. A status the user should act on (sync failing, usage from 90%) puts an `AvatarBadge` dot on the trigger. Settings stays a nav row, never repeated here.
- **Home's header is live, never written.** No brief: the date, a serif headline counted from the queue ("Six things need you." / "All calm."), one muted pulse line (mail in the window, from people, from lists, handled) and **Listen** (a labeled `secondary` `sm` button, `PlayIcon`, never a bare icon) while the queue holds anything. Everything updates on its own as mail arrives. During the first read the headline says so and one muted line with a `Spinner` explains; the empty queue box stays hidden then. The first read lasts until a mailbox has finished one sync (`hasSynced`), and Mail's empty list says the same with a `Spinner`.
- **Picking cards for a batch.** `X` (or the `Checkbox` at the end of each card's header, beside the trigger through `AccordionTrigger`'s `trailing`, never inside it) picks the cursor card, `⌘A` picks all (again: none); the index chip keeps its number. No Pick button in the card's actions: the checkbox is the one control for it. While anything is picked, the section title says "3 picked" and the same row carries **Approve** `⏎` (primary), **Delete** `⌫` (`secondary`, trashes each card's email), **Skip** `S` and **Unpick** `esc` (`ghost-muted`), and `⏎`/`S`/`⌫` act on the picks instead of the cursor card; `esc` clears them. `⌫` on the cursor card alone deletes just that email.
- **A folded queue card acts without opening.** Hovering it swaps its time for icons: approve (`Tick02Icon`, its tooltip the card's verb), Open (`MailOpen01Icon`) and Skip (`NextIcon`), on that card, never the cursor one, and without moving the cursor. A reply has no approve there: a draft is never sent unread. The open card has none, since its buttons already say the same. Short trailing meta (a card's time, Home's recent rows) swaps with its hover actions inside one grid cell (`ROW_SWAP`), never an absolute overlay: the cell is always as wide as the actions, so nothing covers the text, needs a painted background or bumps into a neighbour like the pick checkbox. The overlay (`ROW_ACTIONS`) is only for full-width Mail rows, where the actions sit over the row's own hover background.
- **A board page edits in place.** The title and the description are buttons that turn into seamless fields (native `input` / `textarea` in the same serif and size, `focus-ring` only): the name commits like a Finder rename, the description never on blur — it reads the history again, so only its `warning` button **Save and read again** (`⌘⏎`, consequence beside it) commits and Esc drops it. The header's ⋯ (`ghost-muted` icon) holds Rename (`E`), Change what it collects, Heads-ups (a dialog: the heads-up days), Add chart, and Delete board last — deleting is the one `AlertDialog` (`DeleteBoardDialog`, shared with the sidebar's right-click and ⌘K, which reach the page's edits through `?do=`). Below the header: the summary as a plain `dl` of up to four stats (muted `text-xs` label over `text-xl tabular-nums`), never cards; banners; the chart grid with **Add chart** as its last cell (a popover that takes words); **By who or what** as `SettingsRow`s whose name filters the entries; then the entries under a search field (`/`) with the active filter as a `secondary` chip that clears it. Entries are a J / K list: `⏎`/`O` open the thread, `⌫` takes it off with an Undo toast, `E` renames the board, Esc clears search, then the filter, then the cursor. Each row's ⋯ repeats open and take off. There is no entry edit form: a wrong amount or date is fixed by asking the agent, so the board never turns into a spreadsheet. A chart's bucket, a pie slice or a group click toggles the same filter.
- **Home's Tidy line** sits right under the queue, before Calendar: the same dashed box as the handled summary (`TallyBox`), the total in `font-semibold` then "· 12 to archive · 3 to mark read" per kind, a `link` **Details** (`D`) and a `secondary` **Tidy up** (`T`), both listed in the key hints only while it shows. Details opens a `SettingsGroup` below in the handled list's shape (sender linking to the thread, "effect · why" with only the why masked) with a `ghost-muted` **Keep** at the end of each row. One batch button, never a card per email: this is noise, it must not compete with the queue.
- **Home below the queue** is read-only lists, never more cards: first **Calendar** (the events left today and tomorrow from every mailbox, title linking to that day in `/calendar`, "Today · 14:00 · place" as the description; hidden when there are none), each section a `SettingsGroup` titled like the queue's section, rows a `SettingsRow` whose title links to the thread (or board), a muted `ago` or the amount at the end, then the `ImportanceDot` where importance matters (never an icon column: it indents the text off the group title and the queue cards). The recent list carries Mail's hover icons (`MailRowActions` without Pin: archive, snooze, trash) over its time, and only lists mail still in the inbox, so a row leaves once acted on. Titles and the pulse name the catch-up window ("Also in the last 3 days", `today.period(days)`), never "today", since the page covers every day since the last visit. The saved-time line sits above the dashed handled summary. ## Filter field

Suggestion order is JSX order (`shouldFilter={false}`) — the literal answer first, `Ask AI` last. Chips scroll in a capped row so the field never grows forever, and read as prose (`Is not null`), never raw SQL. AI results report as the input's placeholder behind a check icon, never a toast and never inside the scrolling list. A JSON column adds `Filter inside <column>`, which browses the sampled keys one level at a time by writing the dotted path into the input, so a typed path and a browsed one are the same text; a typed path into a JSON column takes the highlight from `Ask AI`. Quota exhaustion disables the `Ask AI` item alone, never the input. Blur keeps the in-progress stage; only Escape steps back.

## Panes

- **Notice bar** (`components/notice-bar.tsx`): the one place for what the user must act on, a hairline strip (`Item variant="grouped" size="sm"`) above every `/_app` page, one notice at a time, most pressing first: the sign-in Gmail grant lost (Sign in again), an added mailbox lost (Reconnect), Google storage full so Gmail bounces new mail (Free up space, opens Google One's storage page), Gmail's daily sending limit hit (no action, it names when sending works again and leaves on its own), the Calendar scope missing (Allow access). A notice without an action is fine when only time fixes it. Only what the app works without can be put away (×, remembered in `fewmail.dismissed-notices`), and on its own page it stays even then (Calendar on `/calendar`). A transient sync error is not a notice (`hasLostAccess` keeps only grants the user must fix; the sidebar status covers retries). Never plans, usage or upsell here: the never-push rule in `domain.md` holds. A new notice is one entry in `NOTICES` and the list in the bar, not a page-level banner.
- **Reading is a reader, not a list of links**: a fixed `w-96` list (sender · time, a two-line subject, a two-line summary) beside the open newsletter in `ThreadView`, so it is read without leaving the page. The newest opens on arrival, J / K moves the reader with the cursor, Esc folds it to an empty pane, ⏎ reopens it; under 1100px the list and the reader take turns.
- **Pane splits** (navigator, chat, query logger): kit `ResizableGroup`/`ResizablePanel`/`ResizableSeparator` over `motion-panels` (`monorepo.md`; styling only in the kit wrapper, [gotchas.md](gotchas.md)). Sizes are pixel numbers, exactly one pane per group is unsized and fills the rest, and state is controlled: `size`/`onSizeChange` fires on release, `collapsed`/`onCollapsedChange` on a drag past half of `minSize`. The route keeps the size in a seitu `localStorage` value with its bounds beside it, so persistence is the callback itself. Fewmail has two: the sidebar (`_app.tsx`, 200–320px) and the mail reader (`mail.tsx`, 420px–60%, so a 1024px screen keeps a readable list; folded while no thread is open, so the list takes the whole page until an email is opened; the list is the fill pane). A search with no results has its own `Empty` (Nothing found), never the arriving-mail hint. An empty list is the pane empty state too (`Empty size="sm"`, muted mail tile, title and one line), never a bare muted sentence at the top. `KeyHints` never wraps: in a narrow pane it scrolls sideways under `scroll-fade-x`, each hint kept whole.
- **A width is a habit, not a property of the database** — pane sizes are global, not per resource. The runner's results split is the exception: its height sits in the per-tab runner store, because that pane's open state is already per tab.
- The separator is an optional sibling between panes: a sized pane is always draggable by its edge, the separator only adds the visible grip, keyboard and double-click. It takes no flow space (a zero-width slot at the seam, its grip hanging over the sized pane's gutter) and no side — the package derives direction from the pane it sits beside. Where two seams meet, a press within a few px drags both, and hover feedback is shared: one grip lighting alone while two move reads as broken.
- Folds, drags and every size change animate in [motion.md](motion.md).

## Two principles behind the rest

- **The target is the whole surface, not the glyph inside it.** A row's hit area is the row, a strip button's is its hover square, a separator's is the grab strip around its line. A control whose clickable area is its ink is a control the user has to aim at.
- **Anticipate the pointer, not the click.** Work the user has visibly committed to is warmed when the intent shows, so the click finds it ready. Hover is for *revealing* — it never navigates, selects, saves or opens a window, because crossing a surface is not a decision. Pressing is, which is why nav fires on mousedown.

Fewmail's own gaps show as minuses too: a matrix where only one side ever ticks reads as an ad, not a comparison.
- **Nothing waits for the server it can predict.** A toggle, select, rename, delete or event edit shows its outcome on the press and its dialog closes at once; buttons are not disabled while the request runs (a failure toasts and the refetch puts the old state back). A thread link prefetches on pointer enter. An HTML mail starts at its last measured height, so a reopened message never grows into place. A list or panel never claims it is empty before its first answer.
