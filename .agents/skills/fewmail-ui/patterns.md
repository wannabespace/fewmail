# Fewmail patterns

## Controls

- **Control family** (kit): level-3 fill + `shadow-xs` + hairline `border-foreground/4` with `bg-clip-padding` (hover `border-foreground/12`). The hairline is the border, never an outer `ring`: a ring draws outside the box, so a ring-drawn field sat 2px taller than the button beside it (SKILL.md rule 15). Cards and panels keep their outer ring; they never share a row with a control. Hover is `bg-accent`, the one hover surface ([colors.md](colors.md)), never a per-control mix. Focus is `focus-visible:focus-ring`, invalid is `aria-invalid:invalid-ring` — the kit `@utility` pair in globals.css. The focus ring snaps on and only fades out: `focus-ring` drops the control's transition while focused, since a 200ms fade-in reads as lag behind the caret. Focus is always accent and never tinted by state; a control dialing its own `ring-*` pair is the utility going stale, and a `border-destructive` under the invalid ring gives an invalid field more weight than a focused one. Floating panels take the same hairline and `shadow-xl`.
- **Disabled is `opacity-50` + no pointer events on the whole control**, carried by the surface the user sees — a composite control reads the state off its own input (`has-[input:disabled]:`) where the primitive exposes no disabled attribute, or a locked picker looks live.
- **A trigger that opens a menu takes no tooltip** — the menu names its items. Either a button acts or it opens a menu, never `+` plus caret.
- **No bare interactive icons**: ghost hover surface + muted→foreground glyph + tooltip — `Button variant="ghost-muted"` (`outline-muted` for that surface; `ghost-destructive` rests at the same muted glyph and turns red only on hover, so a row's icons read as one set). Upgrade bare ones whenever touching a file.
- An icon-only copy button is kit `CopyIconButton` (`custom/copy-button.tsx`): its `label` is both the tooltip and the `aria-label`. Bare `CopyButton` is for one that carries its own text.
- Any other icon-only button is kit `IconButton` (`custom/icon-button.tsx`): `icon` plus `label`, which is both the tooltip and the `aria-label`, with the tooltip's `shortcut` and `side` passed through. A menu or popover opened by an icon is the same `IconButton`, passed as the trigger's `render` — a bare `Button` with `aria-label` there leaves the icon without a tooltip. A hand-built `Tooltip` around a `Button` with one glyph is upgraded to it whenever its file is touched.
- Icons are Hugeicons only (`HugeiconsIcon` + `@hugeicons/core-free-icons`, `strokeWidth={2}`). Fixed glyphs per concept: Home `Home01Icon`, Mail `Mail01Icon`, Rules and teaching a rule `ZapIcon`, Settings `Settings01Icon`, search `Search01Icon`, anything new `Add01Icon`, compose `PencilEdit02Icon`, check mail `RefreshIcon`, ask AI `AiChat02Icon`, upgrade `CrownIcon`, themes `Sun03Icon`/`Moon02Icon`/`ComputerIcon`. Sidebar row icons sit at `size-4`, 70% opacity, `gap-2` before the label. A glyph that flips with state is one icon with a ternary on `icon`, never two branches.
- Shortcuts render through `ShortcutKbd` (`core/keyboard/`, over the kit's `KbdHotkey`) by id, never a hand-built `Kbd`; a key is a Hugeicons glyph, never the unicode character — ⇧ is `ArrowUpBigIcon`, never an arrow that reads as ↑; ⌫ has no Hugeicon, so the kit draws its own in the same stroke, never the trash can. Modifiers follow macOS order ⌃⌥⇧⌘ (⇧⌘E, never ⌘⇧E). A `Kbd` sizes itself to its host: full size inline, compact (`h-4`, `text-2xs`, 10px glyphs) inside a tooltip or a menu row's shortcut slot, so call sites pass no size. A `Kbd` has no background anywhere — a tinted chip vanishes on coloured buttons and dark surfaces, so shortcuts read by muted text alone. **A button never draws its shortcut in its label** — not a `Kbd`, not a hand-rolled `Esc` span: the hint lives in its tooltip (next bullet). Search fields keep their ⌘F hint in the field's end slot, revealed with the rest on ⌘ hold (SKILL.md rule 9). **Every search field is the kit `SearchInput`** (`custom/search-input.tsx`: the search glyph, the field, a `ghost-muted` `icon-xs` clear ✕ labelled Clear search, then the field's own `end`: a spinner or a key), and the ⌘K palette's input carries the same `SearchClear`; the ✕ shows only while there is text (CSS `:placeholder-shown`, so a search field always has a placeholder, and an uncontrolled field works too) and keeps focus in the field. A field that could only be emptied by selecting its text and deleting it read as stuck.
- A key drawn as a physical key is `Kbd variant="keycap" size="lg"`, animated through `KbdMotion`, never a hand-built raised span.
- **Holding ⌘ shows each control's shortcut glyph, nothing else.** A control with a shortcut passes its `Kbd` as the kit `Tooltip`'s `shortcut` prop, never inside `TooltipContent` (the kit appends it); pass nothing while the control is disabled or the key does not fire here (`window.electron && <Kbd…/>` for Electron-only keys). Hover shows the label plus the glyph; once `useShortcutReveal` reports ⌘ held for a beat (never, while the user has turned it off in Settings → Keyboard), the tooltip opens with the glyph alone, so neighbouring controls' hints stay small and apart, and nothing reflows. A control something else covers (under an open menu or dialog) shows no hint — the kit hit-tests the trigger as the reveal starts, so a menu shows only its own rows' shortcuts. Pressing a shortcut mid-hold ends the reveal until ⌘ is held again, since the dialog or menu it opens would otherwise sit under hints already shown. Two hints that still meet take different `side`s. A control that only appears on hover (a tab's close button) also takes `data-popup-open:opacity-100`, or the hint points at nothing. A hover-only per-row control whose key acts on the cursor row (a mail row's Archive `E`, Trash `⌫`; in Archive, Spam and Trash `E` brings the thread back instead — Move to inbox, or Not spam — and the row's button, the thread's button and the hint follow, via `sweepOf`) passes no shortcut — the hovered row is rarely the cursor row, so the hint would show on one row and lie on the rest; the key lives in the page's `KeyHints`. A text button with a shortcut passes it as the kit `Button`'s `shortcut` prop, which wraps it in a tooltip that carries only the hint (and drops it while disabled); a `Button` used as a menu trigger's `render` takes it the same way.
- **Nav fires on mousedown** (`~/components/link.tsx`, never router `Link`); menu items activate on click (macOS semantics). Imperative press-nav uses `pressNavProps`.
- Tooltips never nest triggers, and multi-node prose goes in **one** block child — `TooltipContent` is `inline-flex`, so sibling nodes lay out as columns. Rich content (a card with icon, heading and paragraphs) is never a tooltip: it is a `Popover` with `openOnHover`, so it gets the popup surface instead of the inverted tooltip ink.
- **Column facts read as SQL clauses**, one per line (`PRIMARY KEY`, `REFERENCES users(id)`, `NOT NULL`, `DEFAULT now()`), never paraphrased labels or constraint names: the audience reads DDL, and invented wording is what they cannot parse. The one exception is `NULLABLE`: a bare `NULL` reads as a value. Set as code with keywords dimmed and identifiers and values at full ink, so the eye lands on what differs per column.
- A `link` button owns its horizontal padding; `px-0!` at a call site is fighting the kit. A lone text action under prose (not in a row of buttons) is `link-muted`, so its glyph starts on the text's edge, and its hover only underlines, keeping the muted colour; a ghost button's padding insets it, and an outline adds a box the prose doesn't have.
- **A command, file or name inside a sentence is kit `InlineCode`** (`components/custom/inline-code.tsx`, also Markdown's inline code and every backticked part of a `FetchingReason`): a `bg-current/10` pill in the colour of the text around it, sized `0.9em` of it, so it reads on the canvas, a card, a muted line and an inverted tooltip in both themes. Inside a flex container (a tooltip, an item title) the sentence goes in one span, or each piece becomes a column. A bare `font-mono` span reads as a typo, not a command. A value the user copies stays muted mono text before its copy button (Settings).
- **A secret is masked unless revealed or being edited.** A one-line secret is kit `PasswordInput`. A multi-line one (an SSH private key) is a textarea while empty, focused or revealed, and otherwise a read-only one-line password input showing its first line, where a paste replaces the whole key: a password input drops line breaks, and a masked textarea scrolls to its caret and shows partial lines. An eye `IconButton` flips it, the same glyph pair as `PasswordInput`.
- **Leaving Edit with unsaved changes asks first**: a router blocker opens an `AlertDialog` (Keep editing, destructive Discard). It ignores the save's own navigation and never vetoes `beforeunload`, which in Electron cancels closing the window with no prompt. Create and the unlock form don't ask: nothing there is a saved record to lose.
- Rows that repeat a label inside another card (the SSH tunnel's Host, User, Password) keep the short visible label and take an `aria-label` naming their group (`SSH host`), so a screen reader tells them from the server's rows.
- **Segmented `Tabs` sit on a `foreground/6` track** so they read on every surface, including the canvas (`muted` matches `body` in dark). A filter strip with more than three options in a resizable pane (mail filters) is the `pill` variant — trackless chips, the active one an ink pill (`bg-foreground text-background`), counts at 60% opacity so they read on both — scrolling sideways (`max-w-full overflow-x-auto scroll-fade-x scrollbar-none`); a segmented track overflows its pane and gets clipped mid-pill, and `line` tabs read as page navigation rather than a quick switch.
- **An off `Switch` sits on a `foreground/15` track**, never `muted`: in dark `muted` matches the canvas and the off track vanishes, leaving a bare thumb. The same goes for an Empty state's glyph tile (`EmptyMedia variant="muted"`): it sits on `foreground/6`.
- **The Mail header is one row: the view picker (a folder's name instead), the mailbox `Select` (only with several mailboxes), and at the end Gmail's own inbox count (`2,345 total`, muted `text-xs tabular-nums`, inbox views only, so nobody takes the held mail for the whole mailbox; one line, and gone below `@xl` of the list column, the column being an `@container`, so a reader or the email sidebar beside the list squeezes the count away before the search field, never wrapping it to two lines) and the search field.** The picker is one outline `sm` `Button` (the view's glyph, its name, the unread count as muted `tabular-nums`, a chevron) opening a `w-160` popover of **inbox views**, the way Spark does it: four cards in a row, each a miniature of the list on top (`ViewSketch`: a level-3 sheet on a canvas well, its rows marked the way the view sorts them), then the name and what it holds (`mail.filterAbout`, never clamped: three lines cut Focused's off mid-phrase), no counts (every view counts the same unread inbox); the folders live only in the sidebar, never in this popover. **A folder is a page of its own, never a view**: Snoozed, Sent, Drafts, Archive, Spam and Trash have their own paths (`/mail/sent`), and on them the picker gives way to the folder's glyph and name as a plain `text-sm font-medium` title, since a Sent trigger opening four inbox views read as Sent being one of them. The views are layouts of the same inbox, not slices of it: **Focused** (`FlashIcon`, the default) groups it by what the user does with it, the way Superhuman, HEY and Apple Mail split an inbox (`GROUP_OF` in `mail-page.tsx`): Important (importance ≥ 2, whatever its kind, so time-sensitive mail always leads the list), People (`person` / `work`, and recent mail not analysed yet, never from an automated address: `isAutomatedSender`), Calendar and travel, Money (bills and receipts), Notifications (services, security, other), Newsletters, Promotions, then Earlier (old mail never analysed); **Unread** (`InboxUnreadIcon`) groups only unread mail that way and puts the rest under Read; **Categories** (`DashboardSquare01Icon`, `?filter=categories`) groups the whole inbox by the analysis category itself, headed by the category's own label (`t.category`), in a fixed order with what needs the user first (`CATEGORY_GROUPS`: Security, where a risk-flagged email always goes, Person, Work, Finance, Receipt, Calendar, Travel, Notification, Newsletter, Promotion, then Other, which also holds mail never analysed, so paged older mail lands in the last, unfolded group), and its rows drop the category label the header already says (chips stay); **Inbox** is one list, newest first. Every group but the last is **folded** to its newest five rows, with Show all N / Show fewer at the end of the group header, so no group pushes the next one away; the last one never folds, since the list pages on through older mail as it scrolls and a folded last group ended it at Show all. People is decided by the sender's address as well as the classifier, since a classifier reads a Google Cloud billing notice as work. There is no separate Group by control, since fourteen buttons in one popover read as settings nobody opened. The picked view is remembered per browser (`fewmail.inbox-view`) and `?filter=` overrides it. Picking a view closes the popover; the active card takes the onboarding preset ring (`ring-2 ring-primary`) and the popover's initial focus, since a focus ring on the first card read as a second pick. `[` / `]` step through the inbox views only, and do nothing in a folder. In Unread, a thread opened from an unread group stays there until the list changes (`keptUnread`), so reading never moves the rows under the cursor. **Search lives in the header, never on a page of its own**: one `sm` search field at the header's end (placeholder just Search or describe, no example: a long one was cut off mid-word in the field; up to `max-w-64`, Gmail's count giving way while a query is on; a muted `Spinner` at its end while a query waits, its ⌘F hint there otherwise), so the list answers in place as it is typed: typing is searching (`?q=` follows, debounced), and clearing the field is leaving it. A swap to a separate search screen with a back button and the list gone read as being sent to another page. `/` and ⌘F focus the field (⌘F anywhere else opens Mail with it focused, `?q=` empty, `mailSearchFieldStore`); a query set from elsewhere (⌘K, a label, Back) refills it. While it is focused and empty, a `w-96` popover under it (`initialFocus`/`finalFocus` off, the field keeping focus on a press) shows Recent (per browser, six, with a `link-muted` Clear in its header) and Tips (Gmail operators that work on received mail, plus one plain-language example only with the agent) as `dense` `SettingsGroup` rows; picking an operator adds it to the field, and one ending in `:` is not searched until something follows it. It searches all received mail, whatever view was picked, in two groups under the usual group headers: **Sender or subject** (a typed word of three letters or more in the sender's name, address or subject) first, then **Mentioned in the text** (what Gmail found only in the body, which the row never shows: a promotion listed under "google" for its Google Play link read as a wrong result); neither folds, and the list stays flat when only one group has rows or the query uses Gmail operators. The reader pane never folds for search: a pane springing shut on `/` and open on every result read as the page breaking. Typing must stay instant: the field is uncontrolled and the list follows it in a `startTransition`; results come in three layers, each merged into the list by thread, newest first, as it arrives: the browser's held rows at once (every held list of received mail, not only the inbox), then Fewmail's own index (`indexOnly`, word beginnings, so a word half typed finds mail Gmail's whole-word search never does), then Gmail's answer (both debounced 400ms, `⏎` at once; the field's spinner runs until every layer has answered, and while rows are already listed a muted Searching your mail… line with a spinner ends them, so nobody takes the first rows for all there is), and the last answer stays while the query is refined, so results grow and shrink instead of blinking empty, and the list is never dimmed while searching (the field's spinner says it). `↓` in the field moves the cursor into the results. Escape steps back one level: blur the field, close the thread, clear the search. Unread rows sit on `bg-background`, read ones on the canvas, so read mail shows at a glance. **Pinned threads open every inbox view** under a sticky Pinned header (count, then a `link-muted` `xs` Show all N / Show fewer at its end): Mail's own two-line rows (a one-line pin with no facts and no code read as a different list), the first three only, so pins never push the inbox down; the list below leaves them out, and the cursor walks the shown pins first. Their hover icons sit at `top-1` to centre on the shorter row; every row's hover set starts with Pin / Unpin (`PinIcon` / `PinOffIcon`), `S` on the cursor row or open thread. Group headers are sticky `bg-body` rows (label + count at 60%) aligned with the row text; while a shown row of the group is unread, a `link-muted` `xs` Mark these read (`MailOpenIcon`) sits before Show all and marks only the shown rows; the cursor walks rows only, in group order.
- **A Mail list never ends where the database does.** Its first page is held mail; scrolling within 600px of the end (an `IntersectionObserver` on a last `li` inside the list's own scroller) reads the next page of the view's own list, past `heldSince` straight from Gmail, with a muted `Spinner` holding the place, until a page comes back empty; a failed page leaves a `link-muted` `xs` Try again in its place and is never read again by itself. A list with nothing held shows that loader, not its Empty state. In Focused and Unread, mail that was never analysed (older than the analysis window) groups under **Earlier**, after Newsletters and unfolded, never under People: People's unanalysed mail is only mail on its way to analysis. **A pointer on a mail row warms it** (`warmThread`): the thread loads and the newest email's images go into the browser cache, so the reader's frame paints at once; images sized 2px or less (tracking pixels) wait for the open, so a hover never tells a sender the mail was read. Rows warmed ahead by the keyboard cursor load only the thread.
- **A one-of-few choice inside a form is a flat `Select`** (below). `Tabs` only switch panels; a row of outline buttons with one filled reads as several actions.
- **A control that submits itself shows its own pending state.** With no button to carry `LoadingContent` (a code input that verifies on the last digit), a muted `Spinner` sits beside the control, positioned out of flow so nothing shifts, and stays through the navigation that follows the request — a dimmed input alone reads as frozen.
- **A server-rendered data page awaits only what its header needs.** The loader awaits the cheap metadata (name, description, filters, so the page head and title are real) and starts the slow read without awaiting it; the table is its own Suspense boundary whose fallback is the kit `TableSkeleton` (`@fewmail/table`) inside the same box, and a header line fed by the read (an updated time) gets a skeleton bar of its exact line height. So the server streams the real header with the skeleton at once and nothing above the table moves when rows arrive. A page-level skeleton cannot know whether the optional header lines exist, so it always shifts something. A re-sort keeps the page: the read uses a `useDeferredValue` of the search, the old rows stay, and the table skeleton covers only the grid on a 150ms CSS delay so a cached sort never flashes.
- **A nav link answers the click before the page does.** Its active state follows the pending location the moment it is pressed. The page area hands over to the route spinner only after a beat: while a different path loads (`status === 'pending'` with a changed pathname, so an invalidate or a search-param change never counts), the page fades out and the spinner fades in, both on a 150ms CSS delay, so a cached page swaps with no flash and only a slow one shows the loader. The router's own pending component never appears here — navigation renders in a transition, which keeps the old page up instead of showing a Suspense fallback.

## Popups and menus

- Context menus are always `AppContextMenu` (data-driven node tree; base-ui on web, native menu over IPC on desktop), never raw kit menu primitives. Destructive item last, after a separator. Every action item and submenu carries an `icon` (hugeicons data, not a node); native menus show its SF Symbol twin from the `sfSymbols` map in `AppContextMenu` (macOS `nativeImage.createMenuSymbol`) — a new icon needs a map entry or it renders web-only. Names are typed (`SFSymbol` from `sf-symbols-typescript`), but the type covers the newest SF Symbols release: a symbol newer than the running macOS still renders empty, silently. Leaf lists that read as options (filter operators, radio choices) stay icon-less.
- A function `items` resolves when the menu opens, on web and native alike, so one menu per card can pick its items from a ref the right-click just set (the diagram's table/column menu).
- **Open in New Window** is the first item of any row menu standing for a route, above a separator. The target must exist before the window opens (a table registers its tab first); `openNewWindow` takes the route href. Secondary desktop windows open offset and never restore maximized — landing on top of the window you came from reads as nothing happened.
- Popups keep the kit's density and radius — don't re-inflate or shrink. `DialogContent` is `p-5` with a `gap-4` grid; the registry's `p-6 gap-6` read as empty against the app's row heights (`AlertDialogContent` still has it). `PopoverContent` owns padding through its `padding` prop (`none` also flattens the base-ui viewport slot); a call site writing `p-0` plus a slot override is the prop going unused.
- **Fill chips in a dialog stay where they are after a pick**: the picked one turns `secondary`, the rest stay `outline`. A row that left on the pick slid the fields and the primary button under the pointer, and the next click pressed it.
- **A preset menu ends with a custom pick.** Time presets (Send later, Snooze) list as an icon-less menu, each with the time it lands on as its `DropdownMenuShortcut` (`EEE p`), leaving out one whose label is untrue at this hour (Later today past midnight, This weekend on a weekend) or that lands on an earlier one's time (`presetTimes`), then a separator and `Pick date & time` (`Calendar03Icon`), which closes the menu and opens a popover anchored to the same trigger: the kit `Calendar` (past days disabled, the user's locale and week start) over a time `Input` and a submit `Button` in one form, so ⏎ in the time field schedules. A time already past marks the field `aria-invalid` instead of scheduling.
- Popovers keep 8px off the window edge and never outgrow the window; a wide fixed-width popover shrinks instead of hugging the edge. The kit caps the height at `--available-height` too, so a tall popover's scrolling body must be a `min-h-0` flex child, or it overflows the cap instead of shrinking.
- Popovers size to content (`w-auto min-w-40`), menus cap at `max-w-80`; only `Select` and `Combobox` match `--anchor-width`, since a menu row is usually longer than its trigger. `CommandInput` only at ~8+ items; hide a sole group heading.
- **Command popups**: state lives as rows in the one `CommandList` — a pinned block outside it is invisible to filter and arrows. The row is the button (state = glyph on the row), a two-state control is one flipping icon, and a picker belongs in the same popover's body, never a child popover. A hover-only ✕ is never the only way out; a nested trailing control `stopPropagation`s on `onPointerDown` *and* `onClick` (cmdk selects on click) and sits absolutely inside the row.
- A hidden control still holds its space, and a control that only appears on hover never moves out from under the pointer.
- **Every amount the app renders goes through `useMoneyFormat`** (`lib/i18n.ts`, `Intl.NumberFormat` in the UI language), the extracted-amount chip too (stored as `1250.00 USD`; anything else is shown as written). Never `toLocaleString()` without the locale: it follows the browser, not the app. Amounts inside model-written sentences stay as written.
- **Dashboard rows are one ↑/↓ list** — Last Opened, the connection rows and New connection — entered with ↓ from an unfocused page; a focused connection row takes the hover fill plus an inset focus ring, since the card clips an outer one.
- **A dashboard row with no link yet shows its loading state**, never a normal look that ignores clicks: while its database's resource row is being fetched, it pulses with the spinner beside the name.
- The `AppMenuButton` ⋯ is always visible in dashboard rows, definitions tables and column headers. Only the navigator's sidebar rows reveal it on hover, because the row's pin can take its place there. A row or header carrying a ⋯ also opens the same items on right-click (`AppContextMenu` on the row or header, one shared `items` function).

## Lists and tables

- **After an action closes rows or cards up under a resting pointer, the pointer clicks nothing for a double click's time or until it moves** (Mail rows, Home's column, Rules): the next row slides in with its Archive, Trash, Send or Delete exactly where the last one was, and the second click of a double click acted on it. `holdClicksUntilMove()` (`lib/still-pointer.ts`; called by `hideThread`, Home's `settle` and a rule's delete) sets `data-pointer-still` on `<html>` until the pointer travels 3px or 300ms pass, whichever comes first, and each action restarts it. Held until a move, the user deleting row after row with a still pointer had to wiggle the mouse before every click. The area carries `STILL_POINTER_GUARD` (`in-data-pointer-still:pointer-events-none`), which also drops its hover reveals. Keys never wait: a keyboard yes keeps the flow. The class goes inside the scroller, never on it (Mail: each `ListRow`), or the wheel stops scrolling; a touch screen is never held. One guard for the whole app: never a second click swallow of its own or a row held in place.
- **A row's one-time code is one soft button** at the row's bottom right, always shown (`CodeActions`): a `secondary` `xs` `CopyButton`, the copy glyph then the code in `text-sm` mono (`data-mask`), the glyph turning to a tick once copied. An outline split button with a chevron menu (Copy and archive / Copy and delete) was a heavy box beside the subject, louder than the email it sat on. **Copying offers to take the email away in its toast**: `Code copied` carries Archive (Delete for mail outside the inbox) as its action, so copy-then-archive is still two clicks without a menu. Loose hover icons beside a chip read as stray clutter. On Home fresh codes are their own group above Decisions, never inside it: a code is not a decision and does not count toward the progress.
- **A spent allowance is one more sentence in Home's serif lead, never a banner** (`today.allowanceSpent`): what waits (summaries, drafts) until the reset day and what the agent still writes down (promises, last days). No button and no upgrade link there: paid plans are mentioned only where `domain.md` → Never push allows; the line exists so the watch never seems to stop silently.
- **Mail rows are two lines, Spark's density with Gmail's full subject.** Unread dot (`bg-primary`, an empty slot when read), then the sender's `sm` avatar beside both lines, as in Worth knowing. **Once someone else wrote in the thread, the row shows everyone in it** (`participants` from `mail.list`, `withParticipants`: web only, so the agent's `list_mail` costs no more): their avatars stacked downward, 8px apart (`ParticipantAvatars isVertical`, the first three, in the order they first wrote, the user once and last; side by side they pushed the two lines right of every other row's), while the reader's line under the title keeps them side by side and their names in place of the sender (`Valerii Strilets, You`; first names past two), so a thread the user already answered reads so before it is opened; pins do the same. The reader names them under the title the same way (`ThreadPeople`, drafts left out), as a `ghost` `sm` button opening a `start`-aligned popover of `compact` `Item`s (the kit's size for this list: no gap between the name and the address, the description `text-xs`, the row `pl-1.5`, since the popover's own padding already sits left of the avatar): each person's avatar, full name with the address right under it, and how many emails they wrote at the end (muted `text-xs`), then whoever only got it in To or Cc (the user's mailboxes left out), with no count. Both stacks ring each avatar in `--avatar-ring`, which `rowSurfaceOf` sets to every fill a row takes (card, read, hover, cursor, open): a fixed ring showed as an outline on a filled row. Line one: sender, then the row's facts in muted `text-xs` pushed to the right beside the time (extracted chips first as `sm` badges, the same height as the thread count, then category, expects a reply, attachment, bulk; what does not fit drops out whole, the sender keeps its width first), time; no importance dot, since a second dot beside the unread one reads as the same mark and importance belongs to Home, the thread and the Important group; line two: the subject, one line. No summary or snippet line: the subject says what the email is, and a third line made the list half as long; the summary lives in the open thread. Never a line of facts under the subject either. **Read mail sinks, as in Gmail, so unread reads at a glance**: unread rows keep the card's `bg-popover`, a semibold sender, a `font-medium` ink subject and an ink time; read rows take `bg-background`, a `text-muted-foreground` sender and subject, a muted time and the avatar at half opacity (the `foreground/70` / `/60` steps alone were too close to tell apart). A card's edge is `SettingsGroup`'s own: the `ring-foreground/4` outside the rows, `shadow-xs` under the last one and no rule under it; edges drawn as borders inside the rows read as a different card from Home's. A row is a thread: a thread of several emails shows its size after the sender as an outline `sm` `Badge`. A bare number and the category beside the sender read as one phrase ("GitHub 2 Notification"), so the count gets an edge and the facts sit apart at the right: who on the left, what on the right. Every row is one thread, never a sender's separate threads folded together: a stack of a sender's quick run of mail had no one email to open, and the sender's other threads unfolding under it read as more of the stack, opening emails nobody expected. The resize grip ends on the column rule at full header height, never past it (see [gotchas.md](gotchas.md)). **Clicking a header cycles its sort** ascending → descending → off: an unsorted column replaces the sort (⇧-click adds it as the next level), a column already in the sort cycles in its place and keeps the rest, so a stray click never wipes a multi-level sort. The keyboard route is the column menu.

- **Editing is a level-3 card over the cell**: a `Popover` anchored on the cell with `sideOffset` of minus the cell's height, so it covers the cell from its top-left and base-ui's collision handling flips it up (bottom on the cell's bottom) or shifts it; at least the cell's width; the cursor ring hides while it is open. Text is a flat growing `Textarea`, dates and times included (no calendar: timestamps are typed or set with `Now`); enum values open a tag `Command` list as wide as its longest value (window-capped), since enum values often share a long prefix and a truncated tag cannot be told apart; JSON and XML open Monaco. A foreign key opens a server-side search over the referenced table matching the key and every text-like column, so a person's name finds their id; each option is the key over a muted preview of the row, and Enter on no match still saves what was typed. The edit's text lives in the cursor store, so it survives its row scrolling out and back.

A rejected value keeps the card open with an inline destructive message, never a toast — except a foreign key's search card, whose text is a search, not a value: no row matching is said by its list's empty state, and a type error under "No matching rows" would only repeat it in the wrong terms. A column whose DEFAULT the engine can write back in an UPDATE offers **Default**, shown in the cell as italic `default`. The keys are the spreadsheet's (`docs/features/table-browser.mdx`).

Two or more selected cells add a summary (count of filled cells; sum, average, min and max for numeric columns) to the grid's bottom dock.

Conditional actions in the toolbar would push the filter field sideways; the dock keeps the toolbar still and sits by what was selected. Callers pass items through `DataGrid`'s `bar`; the summary is the grid's own. Review and Export are `ghost-muted`; Delete (`destructive`) and Save are filled — a ghost button's invisible padding makes the dividers look unevenly spaced. Export is an icon with a tooltip, since the bar can already run wide and Delete beside it shows the count. Counts on its buttons are a `NumberFlow`; the selection summary's stats are plain `tabular-nums` text, since they change on every arrow press and rolling digits there read as noise. A stat past a million shortens (compact, then scientific from 10¹⁵, where compact would grow digits again) and keeps the exact value on hover, so the bar never outgrows the grid; integer columns are summed as `BigInt`, since drivers hand `bigint` over as text and `Number` rounds past 2⁵³.
- **JSON quick look** is a cell-owned popover, so virtualization unmounting the cell takes it away; moving the cursor or editing clears it.

The label is capped at two thirds of the cell so the key always shows; the default comes only from a short list of conventional label names, never a guess beyond it. A column showing labels or a time zone conversion defaults wider to make room for that text.
- **The grid's leading column is pinned to the left edge**: it holds only the row checkbox, one row-height square, and exists only on tables whose rows can be found (`rowIdentity`: a primary key where keys are unique, a unique key with no nullable column, or the comparable columns). Identical rows share one key, so ticking one ticks all of them and the Delete count and select-all count ticked rows, not keys. A new row shows a discard button in that square instead, since the row is not saved and cannot be selected. Scroll padding spans the gutter and every pinned column, so a revealed cell never lands under them.
- **References peek, never navigate**: one peek per grid, anchored to the cell and closed when the grid scrolls ([gotchas.md](gotchas.md)). The ↗ (foreign key) / ↙ (referenced by) buttons are glyph-only ghosts, always visible — a reference is a fact about the value, so it never hides until hover. The popover hangs from the cell itself, not the button. One matching row is a record (fields, then a *Referenced by* list); several are a table whose rows open a record, the matched column dropped since every row repeats it. The header is the trail: earlier hops are crumbs that jump back, no separate Back button, and Escape pops a hop before it closes. Hops swap with an instant exit — a cross-fade layers two tables of different heights. No scroll fades in the peek. The peek is read-only; ↗ inside it always means *show it here*, and leaving for a tab is only the labelled **Open in Table** button.

Name, label and color change only from Edit. Empty states use kit `Empty`; a pane-level one is the kit's icon empty state (icon + title + one line, the app and the share site's one component) on the pane density `Empty size="sm"` (full-page states take the default size) with a `muted` or `destructive` `EmptyMedia` tile — anything added competes with the emptiness, and the emptiness is the message. A popover list's empty state is its `CommandEmpty`: a muted icon over one `text-xs` line, no tile, no title.

Full text sits behind a ghost `Show details`. An error the user can fix from where they are opens in place with its remedies as buttons (outline for leaving and retrying, filled for the fix), rather than sending them to the error page, so the fix is one click from the cause. A value the app could only guess is left blank until the real one arrives, never shown as fact.

It owns the whole keyboard and pointer contract so every list in the app answers the same keys (Enter inserts below the caret, Backspace removes an empty row, ↑/↓ walk, ⌥↑/⌥↓ move the row, Escape blurs, multi-line paste spills, grip drags to reorder), holds itself to one row and marks duplicates itself. ## Messages, alerts, and status

- Alerts: `variant` carries the tint, and there is one density (pane scale) because an alert always sits inside a pane, form or dialog. A call site passing its own padding, radius, text size or tint is a missing variant.
- **An `Alert` reports what already happened.** What a pending action will do belongs on the action: the submit button turns `warning` (`destructive` when it destroys data), is relabelled to the real verb, and carries the consequence in its tooltip — no alert above it and no confirmation dialog in front of it. A confirmation dialog is only for an action with no undo and no draft to back out of. "This field is locked because the shape lives elsewhere" stays a `FieldDescription`; a tinted box for it costs the real warning its weight.
- **An action the current context cannot satisfy is disabled with its reason in a tooltip, never opened to a dead form.** The reason names what is missing ("This schema has no tables to index."), and the button keeps `focusableWhenDisabled` so it still takes hover and a tab stop — a native `disabled` button fires no pointer events, so its tooltip never shows.
- **Any email has its own page, `/mail/$threadId`**: the same `ThreadView` across the whole column, reached from everywhere that is not a list with its own reader — Home's cards (`O`) and rows, Reading, ⌘K's answers, the links Telegram and WhatsApp send. Mail keeps its reader beside the list, with no way to the email's own page: **Open full page** (`⇧O`) in the reader and the sidebar was removed, a reader is the place to read. The page has no ✕: in its place **Back to the list** (`ArrowShrink01Icon`, `esc`) goes back to where it was opened, or to Mail with the email in its reader when the page was the first one; a ✕ beside it did the same thing twice. One email page, never a reader per screen: Home's and Reading's own readers made the same email behave differently by where it was opened. **An email opened from a row never leaves the page**: `ThreadPane` (`components/thread-link.tsx`) shows the same `ThreadView` in a sidebar at the page area's right edge (`thread-pane-area`, under the notice bar), top to bottom, as wide as Mail's reader (`useReaderWidthIn`) with a `foreground/6` hairline on its left and no backdrop; the page area takes the sidebar's width as `padding-right`, so the content narrows beside it instead of hiding under it. No motion either way. `esc`, ✕ or a click on the page close it, with the page's scroll and cursor where they were; the page's own keys rest while it is open (Home's `useHomeFocus`, Reading's `useIsThreadExpanded`). The page itself is for arriving from somewhere else; a jump to it from a row read as leaving the place the person was working in.
- **An email loads as its own outline, never as a blank pane.** Until the thread arrives, `ThreadView` keeps its real header (the ✕ and ↗ work) with a title bar and the action buttons as `Skeleton`s, then `MessageSkeleton`: avatar, name and date, the details line, the summary box when the agent is on, and three body lines; a stacked email draws the same `MessageSkeleton`. A mail's HTML frame measures 0px until it loads, so `HtmlBody` shows the three body lines (`BodySkeleton`) until its first height; a reopened mail keeps its cached height and never flashes them.
- **A short email shows no summary.** Above each email the agent's summary sits in a `bg-secondary/50` box over its chips (category, Expects a reply, dates and codes); when the email's own text is 600 characters or less (`SHORT_BODY_CHARS`, measured on the HTML's text when there is HTML, since a newsletter's text/plain part is often a stub) the sentence and the box go and the chips stay on their own: the summary only repeated the email under it.
- **What the agent did with an email sits beside that email, never stacked above the thread.** A thread shows each settled action (`Mark as read · by a rule`, `· done`, `· failed`) as muted `text-xs` next to the date of its own message, in the expanded header and the folded row alike (`ActionNote`); several on one email join with commas. It takes no flow space (a zero-width slot at the seam, its grip hanging over the sized pane's gutter) and no side — the package derives direction from the pane it sits beside. Where two seams meet, a press within a few px drags both, and hover feedback is shared: one grip lighting alone while two move reads as broken.

## Phones

- **One breakpoint, `md` (768px).** CSS uses `max-md:` / `md:`, JS uses `useIsMobile` (`@fewmail/ui/hooks/use-is-mobile`); both switch at the same width, so never a second breakpoint or a `window.innerWidth` check. Prefer a class to the hook: the hook is for what CSS cannot reach (a pane's size, a portal's box).
- **Below `md` there is no sidebar and no split.** `/_app` drops the resizable sidebar for `MobileBar` (`nav.tsx`): ☰, the logo, Search (⌘K's menu) and Compose, with the same `Sidebar` in a left kit `Sheet` that any navigation closes. A split shows one side at a time: Mail's list hides while an email is open and the reader takes the panes' whole width, the Calendar's event pane covers the calendar, and an email opened from a row (`ThreadPane`) covers the page area instead of making room beside it. Closing (✕, esc) returns to the list.
- **Page columns pad `px-4 pt-6` on a phone** (`max-md:px-4 max-md:pt-6` beside the desktop `px-10 pt-12`), and cards stop bleeding: `smallItemBleedClassName` and `cardsBleedClassName` are `md:` only, so a card sits on the column's edge instead of 2px from the screen's.
- **A row of actions wraps** (`flex-wrap`): compose's footer, the calendar toolbar, Reading's head. A popover wider than a phone caps at `max-w-[calc(100vw-2rem)]` and drops columns (`max-md:grid-cols-2`).
- **Hover-only controls stay hidden on touch** (Tailwind's `hover:` only matches a hovering pointer): every one of them is also on what a tap opens (the reader, an unfolded row), so a phone loses no action, only the shortcut to it. Don't make one show on touch over a row's facts.
- `index.html`'s viewport has `maximum-scale=1` (iOS zooms into a field under 16px on focus and stays there; Safari still lets people pinch) and `interactive-widget=resizes-content`, and the shell is `h-dvh`, so the keyboard shrinks the page instead of covering compose.

## Two principles behind the rest

- **The target is the whole surface, not the glyph inside it.** A row's hit area is the row, a strip button's is its hover square, a separator's is the grab strip around its line. A control whose clickable area is its ink is a control the user has to aim at.
- **Anticipate the pointer, not the click.** Work the user has visibly committed to is warmed when the intent shows, so the click finds it ready. Hover is for *revealing* — it never navigates, selects, saves or opens a window, because crossing a surface is not a decision. Pressing is, which is why nav fires on mousedown.

## Consent cards (on Home)

- **There is no chat.** The agent answers one request at a time (Telegram, WhatsApp, ⌘K's Ask) and an MCP client calls its tools; whatever would send, change Gmail or the calendar, skip a card or add a rule becomes a **consent** card in Home's Decisions, never a dialog and never a transcript: its title is the question ("Send this email?"), its body every input of the tool (`ConsentDetails` in `components/consent-details.tsx`: the email line, To and Cc, the exact text as `DraftText`, the snooze time, the rule and its effect, the event's title · span, place, notes and calendar with a change's old one struck through, the tidy list, the clear-out groups), the reason says who asked ("The agent asks", "Claude asks through MCP"), and the primary button is the tool's verb (`agent.yes`). A chat was tried twice (a column on Home, then a hidden column with an ask field) and dropped: two places to decide was one too many.

## Compose & undo

- **A reply is written under the email it answers, never from the reader's top bar.** The top bar holds what acts on the thread (Archive, Snooze, More); under the last email sits an `outline-muted` field-like `Button` (`MailReply01Icon`, "Write a reply…", `R`) that turns into the `ComposeForm` in place, or the agent's draft (above) when it wrote one. The user's own emails carry an outline **Sent** badge where a sender's address would be: a sent email expanded in its white frame under a folded thread read as a draft nobody could edit. Esc in the editor leaves the draft first; the page's or pane's esc listens with `ignoreDefaultPrevented`, or one press did both.
- One `ComposeForm` everywhere (thread inline reply/forward, the `/compose` page, restored drafts): recipients parse pasted lists (`parseRecipients`), Cc on demand, subject hidden for replies, footer = Send ⌘⏎ · Send later ▾ · Remind me ▾ · attach · Write it for me (replies, Pro) · a muted "Draft saved" · Discard. **Drafts save themselves**: a second after the last change, and again on leaving, to Gmail; saves run one after another so the first one's draft id is reused, a blank email is never saved, and Discard deletes it. There is no Save button. **New mail is a page, never a dialog** (`/compose`, the draft passed in history state): a dialog closed on one stray click or Esc. Escape in the editor blurs it, then leaves the page (back, or home with no history); the draft is already saved. Saved drafts are the Mail → Drafts pill: rows show recipients · subject · snippet with a hover delete, and open on the `/compose` page. "Write it for me" is a `ghost-muted` `sm` button in that footer (`PencilEdit02Icon`; the footer is a `@container`, and below `@xl` it folds to an `icon-sm` `IconButton` with the label as its tooltip, so a reply beside the thread keeps the footer on one line) that fills the editor from the thread in the user's own style, with no instruction field: a field saying "How should it read?" read as nobody knew what — never a separate AI composer.
- Every send shows one toast with **Undo** for the undo window (`UNDO_SEND_SECONDS`); Undo reopens the exact draft. Never confirm-before-send dialogs.
- **Every action is undone or confirmed, never neither.** A Gmail change that has an opposite (archive, trash, report spam, block, snooze, a tidy's archives, a removed chart) ends in a toast with **Undo** that takes back the whole burst under that toast (`useMailActions`, `toastUndo`): a burst is what one click or key did (a stack, the picks), so each action gets its own toast and its Undo never reaches an earlier one. What the server cannot take back but can wait for (a Gmail draft, a calendar event whose guests would get a cancellation, a schedule, a snippet) leaves the screen at once and runs only when its toast closes without Undo (`toastDeferred`); a tab closed before that keeps it. What can neither be undone nor wait (leaving a mailing list, removing a mailbox, disconnecting a bot or an MCP app) asks first through the one `ConfirmDialog` (`confirm()` from anywhere signed in): `warning` takes Enter, since the key that opened it was deliberate, `destructive` keeps Cancel focused. A queue card is itself the question, so approving it never asks again.
- **Work whose outcome only the server knows says it is running**: a `toast.loading` that the result replaces under the same id (approving a card, unsubscribing, tidying, a clear-out). A row that waits for it keeps its place with `LoadingContent` in its button and leaves only when the answer comes, never optimistically. A failure never ends quietly: the error replaces the loading toast, rows hidden for the work come back once the refetch lands (Home's proposals), a partial result says how much did not go through, and a clear-out that moved anything keeps its Undo.
- **A count of emails opens those emails.** A Subscriptions row's name (`⏎` / `O`) and the cleanup card's senders open Mail searching `listSearch` (what the list sent in the last 30 days), a clear-out group's count opens its own Gmail search (`scanClearOut().searches`), the Tidy line's Details lists each email. A number the user is asked to act on is never only a number.
- **A new deploy is one toast that stays** (`t.update.available` + **Reload**, `duration: Infinity`, id `new-version` so it never stacks), never an automatic reload: the user may be mid-draft. It comes from `useNewVersionToast` in `routes/_app.tsx`, so only the app shows it, never the public site.
- A thread opens with its read emails before the last one folded to one line (sender, snippet, date); clicking any or `;` (its `Kbd` on the first folded line) unfolds them all. Folding happens once on load, so opening the thread and marking it read never folds what was unread.
- **A thread ends with its emails and the reply field, nothing about the sender under them.** A person panel there (note, promises, the sender's other waiting threads) repeated Home's cards as run-on paragraphs; what the agent knows about a person is asked in chat (`get_person`). The mail body collapses runs of blank lines.
- **A thread's emails are parted by a rule**: each open email after the first gets a `border-t` with `mt-6 pt-8` around it, since stacked HTML bodies of one sender (a burst of codes) otherwise read as one email. Folded read emails stay dense one-line rows (`gap-2`).
- **An email with an HTML part renders it** in a sandboxed `iframe` (`HtmlBody` in `thread-view.tsx`): white `rounded-xl` page in both themes, because senders lay out for white — unless the mail sets no colours of its own and shows no pictures (no `bgcolor`/`color`/`background` attribute, no colour or background in a `style`, no `img`/`svg`/`video`): a letter typed in Gmail then reads like plain text, on the pane, in the app's ink at 90% and its wax links, flush with the header (the frame copies the tokens' values and takes `color-scheme: light dark` like the app, or it paints an opaque canvas); every link is pinned before render (`frameMail`): web, `mailto:` and `tel:` links open in a new tab whatever their own `target`, `#id` links scroll the page to that spot in the mail, and anything else (relative, `javascript:`, a `#` with no target) stops being a link — a page loaded inside the frame shows as a broken document; meta refresh is stripped; height follows the content. No `allow-scripts`, ever — next to `allow-same-origin` it would give the mail the app's session. Plain-text mail keeps the text block.
- Thread actions: primary row Reply (R), Archive (E), Snooze (H); everything else (Forward F, Unsubscribe, Open in Gmail, Trash #, Block) lives in "More" so the row never grows.
- Mail list rows reveal Archive (E), Snooze (H, a menu) and Trash (#) on hover as `icon-sm` `ghost-muted` icons over the date, on the row's own background (`bg-inherit`, so row hover is solid `bg-accent`); with no thread open the same keys, plus `!` for spam, act on the cursor row. They come from `useMailActions`, the thread view's own set, never a second copy.
- **A row with a code shows it on its summary line**, always visible at the right: the code button above, so copying never opens the email; the subject and summary keep `pr-28` free for it. `Y` copies the cursor row's code with a toast and shows in `KeyHints` only when that row has one. **A fresh code off Home sits in the notice bar**, never a toast: an inbox code under 15 minutes old leads the bar on every page but Home (whose own block has it) and leaves the moment it goes stale; a toast at the bottom right covered other toasts and vanished under the next Undo.

## Marketing site

- Built like Tamery's landing, re-themed: a `Chapter` per feature (border-top header, numbered label, serif `text-display` title left, serif muted `text-brief` description right), the illustration on a `Stage` (level-2 `bg-background` panel, `rounded-3xl`, hairline ring, content `inert`), smaller features in a `FeatureGrid` (icon in a `bg-secondary` square, medium title, muted body). Scroll reveals are CSS `animation-timeline: view()` (`Reveal`), never JS.
- Chapters are ordered by how much the feature sells: Home, replies, Telegram, protection, memory, control. Demos show real-looking content (names, sentences, `ImportanceDot`, `Kbd`), never skeleton lines — the login story is the one exception, it plays in the hero.
- The language select sits in the footer's brand column, under the tagline: the browser already picked the language, so the header keeps only navigation and the two sign-in buttons (it would not fit beside them on a phone).
- The hero headline is the only `text-hero` (4.5rem) besides closing and page titles; everything else stays on the app's scale. One primary button per block ("Start free"), secondary next to it.
- Comparison tables never present both sides as equals: the Fewmail column is a lifted level-3 card (`bg-popover`, `ring-foreground/10`, `shadow-sm`, overhanging the table by `-inset-y-3`) with the logo mark; the competitor's column stays flat. A comparison page is plans and prices first (two cards side by side, one row per plan: name, note, `$` price in serif), then a feature matrix grouped under small section labels. Every cell on both sides is a verdict: a primary tick when the product has it, a muted minus when it does not, plus a short note only when it says something (which plan, how). Fewmail's own gaps show as minuses too: a matrix where only one side ever ticks reads as an ad, not a comparison.
- **Pricing shows only what differs** (`PlanTable` in `components/site.tsx`): the plans head the columns (name, description, price, the trial button, aligned across plans by subgrid rows), then the allowance as numbers (emails, or messages to the agent), one row for the agent with a minus under Free and its features ticked once across Lite, Pro and Max, and one closing row listing what every plan has. Never a row of identical ticks: the paid plans differ only in allowance, and ticks everywhere read as nothing. The column layout starts at `xl`; below it the plans stack (2, then 4 across at `lg`) and every cell names its plan. One footnote under it says the allowance covers everything.
- **Nothing waits for the server it can predict.** A toggle, select, rename, delete or event edit shows its outcome on the press and its dialog closes at once; buttons are not disabled while the request runs (a failure toasts and the refetch puts the old state back). **But a request the user started is never invisible**: once the press has closed the dialog or pane, a `toast.loading` ("Saving the event…") says it is still running and turns, by the same `id`, into the outcome ("Event saved", the Undo toast); a failure dismisses it and the global error toast speaks. Only a change whose whole result is on screen at once (a toggle, a pin, a read mark on a row) needs no toast. A thread link prefetches on pointer enter. An HTML mail starts at its last measured height, so a reopened message never grows into place. A list or panel never claims it is empty before its first answer.
- **Saving a recurring event asks what it reaches, at the save.** The event pane's Save turns into a menu trigger for an occurrence of a recurring event (This event, This and following events, All events; icon-less, an option list), opened upward from the button; `⌘⏎` and `⏎` in the title validate first and then open the same menu. Never a remembered or pre-picked scope beside Save: a default that silently picks "this event" is how a series ends up half renamed.
- **Files are kit `Attachment` chips in an `AttachmentGroup`** (`components/attachments.tsx`, `FileChip`: `sm`, the type's glyph or the image itself as media, name masked, size from `useFileSize`). Under an email the whole chip is an `AttachmentTrigger` link opening the file in a new tab; in the composer it carries one `icon-xs` ghost-muted remove `IconButton`. Dragging files over the composer lays a dashed `border-primary/40` overlay saying where they go; nothing moves. The composer's action row keeps Discard as a `ghost-destructive` trash `IconButton` beside the paperclip, so "Draft saved" never truncates. A Mail row marks an email with files by a `size-3` paperclip in its meta line (screen-reader text, no word). A spam email's hidden images are one muted line above the body with an `xs` secondary Show images; a spam file opens through the `warning` `confirm`.
