# Architecture

| Topic | Rule |
| --- | --- |
| Layout | `apps/api` (Bun + Hono), `apps/web` (Vite SPA, React 19, TanStack Router + Query), `packages/db` (Drizzle + Postgres), `packages/shared` (enums and helpers shared by both), `packages/ui` (the kit). |
| Services | `apps/api/services/*` own all behaviour and take `userId` first. `orpc/router.ts` (web), `mcp.ts` (MCP over Streamable HTTP, API-key auth) and `telegram.ts` (grammY) only adapt them. Errors a user can cause throw `NotFoundError`, mapped per surface. |
| API layer | oRPC with arktype input schemas. The web imports the `Router` type from `@fewmail/api/router`; outputs typed via `RouterOutputs`. The API package uses relative imports (no `~/` alias) because the web type-checks it. |
| Auth | Better Auth, Google only, with the `gmail.modify` scope, `accessType: offline` and `prompt: consent` (no refresh token otherwise). OAuth tokens are encrypted by Better Auth. Gmail access tokens come from `auth.api.getAccessToken` with the user's Google account row id. |
| Gmail | Plain REST in `lib/gmail.ts` (no googleapis SDK). Sync: first run takes `in:inbox newer_than:3d` (60) plus recent sent mail for voice; later runs use the History API from `mailboxes.historyId`, falling back to a full first run when history expired (404). Search goes through Gmail's own search (`q`), since subjects and bodies are encrypted in our DB. |
| Worker | In-process (`worker.ts`), one tick a minute: sync mailboxes older than 2 minutes, write due briefs (and send them to Telegram), push importance-3 actions to Telegram once (`actions.notifiedAt`). A per-key in-memory lock prevents overlap. Move to a queue only when there is more than one API instance. |
| AI | Per email, **Jev** (TypeSafe, `lib/jev.ts`, `services/classify.ts`) makes every typed decision in one call — category, importance score, needs-reply, suggested action, matching rule — and the LLM only writes text (summary, reason, button label, extracted facts) for mail that is not noise; without `TYPESAFE_API_KEY` the LLM does both. OpenRouter through the AI SDK (`lib/ai.ts`): `models.fast` (Claude Haiku, Gemini Flash fallback) analyses every message with structured output; `models.writer` (Claude Sonnet) writes drafts and briefs. Prompts never let the model invent facts; drafts contain no placeholders. |
| Database | Drizzle (`packages/db`), uuid v7 ids, `snake_case` tables, `encryptedText` for subjects, snippets, bodies, summaries, drafts and briefs (AES-GCM, `ENCRYPTION_SECRET`). Migrations: `pnpm db:generate` then `pnpm db:migrate`. |
| Integrations | Telegram: deep link `t.me/<bot>?start=<linkCode>` links a chat; inline buttons approve/skip/redraft; webhook when `TELEGRAM_WEBHOOK_SECRET` is set, long polling otherwise. MCP: per-user API keys (`fm_…`, stored as sha256), tools mirror the services; `approve_action` sends mail, so its description tells the client to confirm with the user. |
| Client state | TanStack Query via `orpc.*.queryOptions()`; optimistic removal from the queue on approve/skip. No global stores. |
| i18n | `packages/shared/i18n`: `locales.ts` (supported `LOCALES`, `matchLocale`, typed `plural` whose forms are `(n) => string`, and `Rich<Slot>` for messages with nodes inside such as links), `messages/en.ts` is the source of truth and `Messages = typeof en`; every other locale is `: Messages`, so a missing or mistyped key fails the type check. **No string placeholders**: anything with a parameter is a function, anything with a link or node is `Rich`. Adding a string means adding it to every locale in the same task. Web: `useT()`, `useDates()`, `localeStore` (`apps/web/src/lib/i18n.ts`); API/Telegram: `messages[settings.language]`. Right-to-left languages are not supported yet (layout uses physical `ml-`/`pl-`). |
| Legal & account | `/privacy` and `/terms` are public routes rendering `apps/web/src/legal/*.md`; they describe exactly what the code does (Google API Limited Use included) — a change in what data is read, stored, sent or to whom updates them and `LEGAL_UPDATED_AT` in the same task. Account deletion is Better Auth `deleteUser`: it revokes the Google grant first, then every table cascades from `users`. |
| Plans | `services/plan.ts`: `getPlanInfo` (free / trial / pro from `subscriptions` with an active Stripe status, else `trial_ends_at`), `hasAgent`. Server-side gating: oRPC `agent` middleware on every procedure that runs a model or is agent-only; MCP answers 403 and Telegram replies `proOnly` for Free; the worker skips analysis and briefs for Free. Sync and simple rules run for everyone. AI analysis only looks at the last 3 days, so an upgrade never pays for the backlog. The web reads `me.plan` (`useHasAgent`) and removes AI surfaces instead of disabling them. |
| Billing | Stripe like Tamery but lean (`services/billing.ts`): Checkout (`STRIPE_PRICE_ID`, no Stripe trial — ours is card-free), Billing Portal, and one webhook `POST /stripe/webhook` that upserts `subscriptions` by `stripe_subscription_id` for `customer.subscription.created|updated|deleted`. `userId` travels in subscription metadata. |
| Sending | Everything leaves through the **outbox** (`services/outbox.ts`): manual mail, approved drafts (web, Telegram, MCP) and scheduled mail. A row waits `UNDO_SEND_SECONDS` (or until its `sendAt`), an in-process timer dispatches it exactly and the worker sweep catches restarts; dispatch claims the row atomically (`scheduled → sending`) so Undo and sending never both win. Undo (`cancelMail`) returns the draft to the editor, or an approved action back to the queue. Mail is multipart (text + HTML from the Tiptap editor). |
| Reminders | `reminders` holds snoozes (Gmail INBOX removed, restored with UNREAD when due) and follow-ups (due unless a non-own message arrived in the thread since `since`). A user-set "remind if no reply" works on Free by resurfacing the thread; on Pro the agent also detects sent mail that expects an answer (Jev noul) and turns a due follow-up into a `follow_up` action. |
| Inbox state | Sync reads Gmail history for new messages **and** label changes, so archive/read/snooze done in other clients shows up; `changeThreadLabels` (`services/thread-labels.ts`) changes Gmail and mirrors locally at once. Mail actions work on whole threads. |
| Composer | `apps/web/src/components/composer` (Tiptap v3, pinned): bubble menu, `;` snippets, ghost-text autocomplete (`mail.complete`: Mistral Codestral FIM, chat-model fallback), Mod-Enter / Escape ladder handled inside the editor. HTML ↔ text helpers live in `@fewmail/shared/email` for both web and API. |
| Ask AI | `services/ask.ts`: the fast model turns a question into a Gmail search, the writer answers from the found mail with `[n]` citations shown as sources in ⌘K. |
| Spam shield | `services/spam.ts`, on every plan, runs in sync before simple rules and the agent. `sender_reports` keeps one vote per user and sender as **HMAC hashes** (keyed with `BETTER_AUTH_SECRET`; rotating it resets reputation) — never addresses or content. Your own vote applies to you at once; community spam needs ≥ 3 distinct reporters (≥ 5 for a company domain; freemail domains never count) and a Laplace-smoothed spam share ≥ 0.8, so one user can never flag a sender for others and not-spam votes pull it back. People you have written to are never moved by community votes. Moves are `spam` actions (`auto_done`), reviewable in the Spam tab and the handled summary. The privacy policy describes exactly this — keep them in sync. |
